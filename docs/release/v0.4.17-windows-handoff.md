# FyAgent v0.4.17 换机交接

截至 2026 年 11 月 20 日，v0.4.17 的功能和版本准备已合入 `main`。Windows x64、ARM64 候选包都已签名，在本机用 Windows SDK 验签通过。无人值守签名仍待开通和演练，Windows 安装体验仍待实机验收。GitHub 当前公开稳定版为 [v0.4.16](https://github.com/fy-agent/fyagent/releases/tag/v0.4.16)。发布工作集中在 [PR #436](https://github.com/fy-agent/fyagent/pull/436)。

## 在另一台电脑接手

从一个新目录执行，需要 Git 和已登录的 GitHub CLI。本机首次在较深的 Windows 目录克隆时，归档文件报“文件名太长”。下面的命令只为这份仓库启用长路径。

```sh
git clone --config core.longpaths=true https://github.com/fy-agent/fyagent.git fyagent-0417
cd fyagent-0417
gh pr checkout 436
git rev-parse HEAD
gh pr view 436 --json headRefOid --jq .headRefOid
gh pr checks 436
```

两条命令打印的完整提交号应相同。开发分支是 `codex/windows-acceptance-signing-20261120`。候选包来自 `main` 的 `b7bc8c583e885a29354e21d4a15aa56da403c56e`。拉取 PR 可得到后续的发布流程修复。需要运行代码时，按[开发环境说明](../../CONTRIBUTING.md#development-setup)安装仓库指定版本。

## 如何核对已有候选包

两个安装包的构建作业均成功，来自 [Release 44596245772，第 1 次运行](https://github.com/fy-agent/fyagent/actions/runs/44596245772)。该运行在汇总证明时失败。以下指纹对应后来用公司 Certum 证书签过的候选文件。两次 `signtool verify /pa /all /v /tw` 都以 0 退出，均有可信时间戳，警告和错误均为 0。

| 文件 | SHA-256 |
| --- | --- |
| `FyAgent-0.4.17-Windows-x64-setup.exe` | `93b3293db8f50482dac76c533e6cf77eed5fc9cde512905c147b0c667e56c55f` |
| `FyAgent-0.4.17-Windows-arm64-setup.exe` | `aabfea369eca9730e060e2edf8d5a9c1a9fc7d717efc0e8cc3aa32d3db7f8a0b` |
| `FyAgent-0.4.17-Windows-signed.zip` | `52f14cbf6e45e6d6de12673eef652c3ea14f4d1d44b4cc39cfc576667c49e621` |

ZIP 内有两个签名安装包和 `local-signing-evidence.json`。在 Windows 下载目录执行 `Get-FileHash .\FyAgent-0.4.17-Windows-signed.zip -Algorithm SHA256`，与表中最后一行核对。

2. **PR 合入后，发布维护者在受保护的主线上重新预构建。** 记录成功的 Release 运行 ID、尝试次数和完整源码提交，用它们触发 `Windows installer lifecycle`。分别保留 x64 和 ARM64 安装、卸载作业结果。在干净的 Windows 客户端记录 SmartScreen、UAC、首次启动，以及从 v0.4.16 升级的结果和安装包指纹。[Windows 验收步骤](../fyagent/development/ci-release/release.md#windows-acceptance-and-signed-rehearsal)
