# VibeKey 宣发与产品设计对照审计

## 结论

VibeKey 最值得 FyAgent 继承的不是硬件外形，而是它把复杂操作压缩成“一个动作、一个状态、一个结果”的表达方式。FyAgent 当前产品能力更完整，宣发却仍容易落成功能清单，缺少这种短路径叙事。README 已移除带 `CC Switch` 身份的旧截图，并补入 “For You Agent——个人随身数字人格” 的产品沿革；真实界面仍按截图任务卡独立验收。

本审计建议：

- **继承** VibeKey 的即时控制感、状态可见性、四步新手路径和 90 秒内讲清价值的内容纪律。
- **改造** “插上即用”为 FyAgent 已验证的“一处管理、快速切换、统一同步”；用软件控制面隐喻，不继续硬件叙事。
- **放弃** Claude-only、硬件键盘、试用额度、语音输入、众筹价格、官方合作和未经验证的市场数字。
- 概念图、真实 UI 截图、Logo 母版必须分层管理；任何概念图都不得冒充产品界面或运行时证据。

## 2. VibeKey 当时的产品与宣发设计

### 产品定位

- 愿景：让任何人都能自信使用 AI 编程工具。
- 定位：Claude Code 的“物理界面层”。
- 核心卖点：插上即用，由驱动完成环境配置，降低命令行与 API Key 门槛。
- 核心操作：接受、拒绝、重试、中断、模式切换、模型切换、清空、压缩和语音输入。
- 用户扩展路径：程序员“酷周边” → 职场新手“AI 入门神器” → 家庭用户“家庭 AI 助手”。

### 交互与视觉

- UI 原则：极简、状态可见、即时反馈、低干扰；首次配置目标为 5 分钟内完成，日常隐藏到系统托盘。
- 引导流程：环境检测 → 安装 Claude Code → 配置 API → 完成并尝试第一个指令。
- 视觉规范：深灰背景、深蓝/青色主调，绿色/橙色/红色承担状态；卡片和圆角控制面板为主要界面语言。
- 宣发节奏：先做工业设计与渲染图，再拍 90 秒视频、积累种子用户、众筹上线；渠道覆盖即刻、V2EX、小红书、X、微信群、B 站、知乎、播客和公众号。

### 证据冲突

归档中的硬件文档明确写着“MVP 不搭载屏幕，使用 LED 指示灯替代”，产品概念图却展示了带长条屏幕的设备。README 同时把“完成工业设计渲染图”列为待办，因此该图片只能视为方向概念，不能证明实际产品形态。

私有原型代码检出也只能证明 React/Tauri 组件和 Rust 模块的脚手架：目录没有 `.git`，当前文件清单缺少可独立启动前端所需的 `index.html`、TypeScript/Vite/Tailwind 配置和锁文件。本轮没有运行时截图或可复现构建证据，不能把 README 中的功能表当成已交付产品。

商业计划中的价格、试用额度、合作可能性、众筹目标和市场数据没有交付证据。本轮不将这些内容迁移为 FyAgent 的商业结论。

## 3. 与当前 FyAgent 的对照

| 维度     | VibeKey                           | 当前 FyAgent                                          | 对宣发的含义                                                |
| -------- | --------------------------------- | ----------------------------------------------------- | ----------------------------------------------------------- |
| 产品形态 | Claude Code 专用硬件控制器 + 驱动 | 管理 8 个 AI 工具的跨平台桌面应用                     | 从“硬件入口”改为“配置与运行控制面”                          |
| 核心问题 | 安装、命令和操作方式太技术        | 多工具配置分散、供应商切换和扩展同步复杂              | 讲清“少编辑、多控制”，不泛化到所有 AI 场景                  |
| 主承诺   | 插上即用                          | 一处管理、快速切换、统一 MCP/Prompts/Skills、原子写入 | 主视觉应表现“散 → 统 → 可控”                                |
| 高频动作 | 接受/拒绝/重试、模式/模型切换     | 导入供应商、启用/切换、托盘切换、同步扩展、代理接管   | 用 3 个真实工作流替代长功能列表                             |
| 状态反馈 | LED 显示模式、模型、录音          | 当前供应商、健康状态、用量、代理/故障转移             | 状态色可继承，具体数据必须来自真实 UI                       |
| 新手引导 | 4 步向导                          | README 有快速开始，但首屏缺少完整视觉路径             | 增加“第一次完成切换”的四步讲解资产                          |
| 视觉证据 | 文档线框 + 驱动原型 + 概念图      | 真实应用截图 + 品牌 Logo + 生图概念                   | 真实截图优先，插图只解释抽象关系                            |
| 当前风险 | 概念图与 MVP 决策冲突             | 旧截图带旧品牌；v1 生图重画 Logo；v2 线路粗糙         | 建立来源、状态、发布许可和确定性合成门禁；当前候选推进至 v3 |

## 4. 迁移决策：继承 / 改造 / 放弃

| 决策 | 元素                               | FyAgent 落地方式                                                         |
| ---- | ---------------------------------- | ------------------------------------------------------------------------ |
| 继承 | 一个动作对应一个清晰结果           | 每张讲解图只讲一个工作流，例如“导入 → 启用 → 写入 → 生效”                |
| 继承 | 状态可见                           | 统一使用青蓝主信号、绿色健康、橙色注意、红色失败；状态含义不可仅靠颜色   |
| 继承 | 新手四步路径                       | 做“选择工具 → 添加供应商 → 启用 → 在托盘快速切换”的真实步骤图            |
| 继承 | 90 秒内讲清价值                    | 视频结构固定为痛点 15 秒、核心动作 45 秒、可信证据 20 秒、CTA 10 秒      |
| 改造 | 触觉化控制台                       | 使用抽象软件控制面、配置卡片与数据轨道；禁止画成键盘、USB Hub 或实体设备 |
| 改造 | “插上即用”                         | 改为“告别手改配置，一处管理八个工具”；不得承诺零配置或所有工具热切换     |
| 改造 | 极客周边身份                       | 改为专业开发者工具的可信、克制、可验证视觉，不做玩具化硬件广告           |
| 放弃 | Claude-only、模型旋钮、语音键      | 与当前产品定位无关，不进入文案和图像                                     |
| 放弃 | 试用额度、众筹、定价、官方联合品牌 | 无当前合同或证据，不进入 FyAgent 路线图                                  |
| 放弃 | 家庭用户/全民 AI 助手扩张          | 当前产品事实不支持，先服务已有开发工具用户                               |

## 5. 当前对外叙事建议

建议主标题：

> 把八个 AI 工具的配置，收进一个桌面控制台

建议副标题：

> 不再反复手改 JSON、TOML 和 `.env`。在 FyAgent 中管理供应商、MCP、Prompts 与 Skills，并从主界面或系统托盘快速切换。

首批只讲三个可验证故事：

1. **统一供应商管理**：从分散配置文件到一个可视化入口。
2. **一次切换，明确生效**：显示当前供应商、写入边界和需要重启的工具差异。
3. **扩展统一同步**：用真实界面说明 MCP、Prompts、Skills 的安装、同步与备份。

涉及“50+ 预设”“8 个工具”“热切换”“故障转移”等数字或能力时，以目标发布 SHA 的 README、源码合同和运行截图为准，不从历史文案复制。

## 6. 视觉开展顺序

### P0：先恢复可信度

- 重拍 README 六张三语截图，移除可见的 `CC Switch` 身份；实际数量以截图审计为准。
- 用真实运行时截图建立主界面、添加供应商、切换成功三个 proof frame。
- 所有插图登记 `concept` / `approved_background` / `final`；真实截图登记 `runtime_screenshot`。

### P1：建立可复用资产系统

- 使用 [v3 对称线路软件编排样例](visual-direction-sample-v3.md) 作为方向候选；v2 因线路网格和端口不一致保留为被替代记录。
- 生成内容只负责背景、材质和抽象关系；Logo、标题、CTA、功能标签用原始资产和 HTML/SVG 确定性合成。
- 输出 16:9 Hero、1200×630 OG、4:5 中文社区海报和 1:1 发布卡；每个画幅独立检查安全区，不直接自动裁切。

### P2：形成内容闭环

- 制作 30 秒、60 秒、90 秒三个讲解脚本，复用同一组真实工作流。
- 每条内容只设置一个 CTA：查看界面、阅读使用手册或下载并核验 Release。
- 渠道选择在真实受众数据出现后再定，不沿用 VibeKey 的众筹/KOL 目标数字。
