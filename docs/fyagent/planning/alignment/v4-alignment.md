# CC Switch v4.0 对齐：先继承成熟实现，再补 FyAgent 的差值

2026-10-04。总票 [#204](https://github.com/fy-agent/fyagent/issues/204)，文档草稿 [#214](https://github.com/fy-agent/fyagent/pull/214)。此补充修正上一版“保持现有界面”容易造成的误解：**优先迁入上游已实现的算法、组件结构和交互流程，FyAgent 只调整已有架构接口、品牌及确有差异的行为。** 不再把前端迁移理解为只借设计理念、页面全部重做。

## 1. 版本与来源必须分开说

用户所指上游版本在官方仓库中为 **v4.0.0**，不是 FyAgent 的 v0.4.x。核查时该 Release 标为 **prerelease**；稳定版为 v3.20.4。此次固定 [v4 源码 412579f9](https://github.com/farion1231/cc-switch/tree/412579f9ad81ed3c045476198aa9f8d1de36a2ae)，不把浮动 main 当成发布内容。

**上一版九张票并非全是 v4 新发布的功能。** v4 包含早期版本成果；FyAgent 增强和交付验收也混在了工作包里。应按下面的层次认领：

|---|---|---|---|

## 2. 已找到的直接复用材料

“接近原样”是代码审计判断，仍需接口适配、编译与原测试验证；不意味着已经移植成功。完整 15 项入口、目标路径和依赖见[代码复用表](reuse-and-provenance.md)。

| 材料 | 不必重复开发什么 | 主要适配点 |
|---|---|---|
| `jsonc_document.rs` | JSONC/JSON5 注释和格式保留算法 | 沿现有路径选择、锁、备份；两端已有相同关键依赖 |
| `mcpDraft.ts` | 粘贴 JSON/TOML 识别、校验、额外字段保留与密钥掩码规则 | 接已有 MCP 类型和目标列表 |
| `modelMetadataFill.ts`、`quotaRules.ts` | 模型只补空值、额度剩余量、过期与倒计时规则 | 类型、中文文案、账号数据来源 |
| `FetchedModelPicker.tsx` | 搜索、批量选择、已配置项与输入法交互 | 替换基础组件与文案；保留 props 和流程 |
| `mode/stack.rs` | 模型 ID 编解码、稳定 key、未知前缀拒绝与默认路由 | 接现有代理、凭据和配置计划；不混入 failover |
| 会话 `model/content/providers`、`reader/turns`、`SessionReader` | typed blocks、按轮组织、折叠、搜索展开与阅读布局 | 新增阅读接口；保留已有恢复/迁移功能 |
| `ProviderCard`、`ProviderForm`、`AppsPage` 等组件结构 | 成熟的信息层级、操作位置和按需展开方式 | 映射 FyAgent 样式、FeaturePorts、查询与通知；只接一个权威状态 |

完整页面存在 Tailwind、i18n、图标、通知、虚拟列表与 Tauri API 差异。这意味着需要写适配层，**不是页面需要重新设计一遍**。按实际迁入组件的依赖范围决定引入或替换，避免整包搬进不使用的编辑器/图表依赖。

## 3. 首版页面的信息展示合同

上游有 `docs/design-system.html` 和 Pi 专项 UI/UX 文档，实际组件与发布截图提供更强证据。资料不总是同步：旧设计文档仍提到后来删除的命令面板，Pi 文档的“立即显示完整表单”也被最终统一添加选择器覆盖。**最终固定版本源码优先，文档用于理解理由。** 逐页出处与冲突记录见[上游 UI 证据](upstream-v4-ui-evidence.md)。

| 页面 | 用户默认看见 | 操作后再看见 | 首屏不堆什么 |
|---|---|---|---|
| 供应商列表 | 名称、少量模式/官方状态、备注或绑定信息、额度、必要操作 | 模型在编辑中；默认、删除、测速等按适用性进更多菜单 | 完整模型列表、原始配置、端口和日志、恢复内部编号 |
| 连接模式 | 直连/路由/聚合三个紧凑标签 | 浏览非生效模式时说明当前状态，并给明确启用动作；需要时确认影响 | 三块大型概念说明卡；把“正在看”伪装成“已经启用” |
| 聚合列表 | 默认来源、已添加、可添加；行主操作添加/移除 | 已添加项的“设为默认”进更多菜单；变更后需要时提示宿主重载 | 每一行重复一组抢眼按钮；误承诺聚合自动故障转移 |
| 添加/编辑 | 预设选择、连接必填项；适用模式下用简化表单 | 模型能力、思考、请求覆盖等按需展开；高级已有值可展开提醒 | 大段 JSON、所有协议开关同时铺开；给不存在的能力造设置 |
| 软件发现 | 名称、实际路径、来源、版本；有更新才给升级 | 额外安装副本展开；诊断和手动命令放二级入口 | 把“显示入口”伪装成启停/卸载；默认贴安装命令教程 |
| Skills/MCP/提示词 | 资源、来源、分配/更新状态和当前操作 | 批量导入结果、目标失败及重试；更新发生冲突时再进入处理 | 日常列表常驻整套备份、digest、变更引擎和调试信息 |
| 会话 | 正文、轮次、执行摘要、失败标记 | 工具参数/输出展开；定位搜索结果；目录导航 | 全部工具 JSON 一次铺满，压掉对话内容 |
| 用量 | 核心指标、范围/应用筛选、趋势与明细入口 | 更多指标、定价/数据来源与具体请求 | 数据缺失显示成零；估算速度/成本显示成精确实测账单 |

**按客户端保留语义差异。** 上表的当前供应商/默认操作不能机械套到 Pi。Pi 的配置成员管理与原生模型选择有不同职责；原生状态未能可靠读取时不能靠数据库猜测。其他客户端也必须按真实支持决定显示/禁用/隐藏。

新版[两页可点击草图](preview/v4-aligned-pages.html)展示供应商/聚合、添加/编辑弹窗、软件发现；保留蓝色主题，评审依据在产品区域外折叠。旧的资源更新与原生入口草图保留作专项实验，**不再作为普通首页信息密度的基线**。新草图没有真实数据/网络/配置读写，也没有做完整预设库和全客户端界面。

## 4. 两项确实需要自己补的部分

**Skills 完整更新保证：** 固定 v4 的 `services/skill.rs:1618` 仍忽略备份错误，通用目标同步失败仍可能仅写日志后整体返回成功。上游有 Pi/Mcode 专项保护，可复用其 staging，但不代表所有副本完整快照和恢复已经解决。FyAgent 必须接现有 ChangePlan 补齐承诺；不能搬一个上游更新按钮就宣布安全更新完成。

**用户确认与外部修改：** 上游 live engine 会在外部变化后重新计算写入，而 FyAgent 已确认预览要求旧计划失效。可复用 patch/project 算法，但不能绕过重新预览继续写。此要求主要体现在发生冲突的时刻，不应让普通用户日常填写内部计划字段。

## 5. 下一轮怎样开始

1. 以 v4 页面结构和组件为设计起点。先做供应商/模型选择器、额度、Apps 这组可见页面适配；每页注明来源组件、接口替换、继承行为和额外行为。草图先可评审，真实数据接线随底座完成。
2. 来源集成由唯一负责人按现有 two-parent/tag 规则进行。稳定段是兼容性检查点，v4 重做的模块采用最终实现，避免先完整适配旧页面又重做一次。沿用既有 FyAgent 身份、数据及恢复边界。
3. 资源、客户端、聚合、会话按模块推进，先迁原算法及测试，再补本地差值。共享 writer、数据库和 DTO 串行协调；各设备按已有 Issue 认领。
4. #212 原生入口独立验证，不增加 v4 迁移的必经依赖。#213 同时准备样本，待构建冻结再验证 Windows/Mac，不能把规划和模拟当成产品上线。

本轮结论是 `code_audit` 和设计 mock：未迁移运行时代码、未更换用户安装、未承诺编译通过或原生客户端可用。新版草图的静态及非浏览器状态逻辑检查记录在 [verification.json](preview/verification.json)，不计浏览器截图或像素验收。
