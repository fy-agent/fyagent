# FyAgent 前端交互重构 v3｜提示词与 A-to-A 工作流

> 用途：让后续生图、评审、实现和验收都复用同一事实基线。
>
> 原则：先冻结设计，再写代码；先验证运行态，再讨论严格还原。

## 1. 生图主提示词

```text
为 FyAgent 创建生产级、可交付开发的 16:9 桌面端高保真 UI。

输入约定：
- 参考图 1 是已确认的 FyAgent v3 视觉基线，负责颜色、质感、字体层级和组件语言。
- 参考图 2 是线框原型，负责信息架构、按钮位置、页面分区和交互入口。

必须保持：
- macOS 桌面窗口壳层与固定左侧导航；
- 深海军蓝到皇家蓝背景、克制的蓝色极光/电路线条；
- liquid-glass 半透明面板、细蓝色描边、柔和阴影、16–20 px 圆角；
- cyan/blue 用于 active、focus、primary action，危险动作只使用克制的红色描边；
- 清晰、可读、拼写正确的中文；
- 高信息密度但不拥挤，组件对齐适合工程落地。

本轮是交互位置与信息架构重构，不是主题重做。

禁止：
- 紫色/粉色渐变、通用营销落地页、统计仪表盘；
- 增加线框和页面规格之外的主操作；
- 随机文案、乱码、错误的管理入口；
- 真实密钥、真实个人记忆、绝对本地路径；
- 水印、浮窗、透视展示、设备模型或背景场景。

输出：正面平视的完整桌面产品截图，清晰锐利，适合产品评审与工程交接。
```

## 3. 单页生成补充模板

把下列变量附加到主提示词，不要重复改写视觉基线：

```text
页面编号与名称：{screen_id} {screen_name}
使用线框：{wireframe_page}
当前主体：{selected_agent_or_resource}
Active 导航：{active_nav}
页面区域：{regions}
核心动作：{actions}
列表内容：{items}
开关/选择状态：{states}
精确文案修正：{copy_fixes}
隐私替换：{safe_sample_content}
不得出现：{screen_specific_negatives}
```

### 页面级关键补充

- 01–02：相同软件列表骨架，只切换扫描完成/扫描中状态，避免两个页面发生布局漂移。
- 03–06：相同 Agent 壳层、相同四段页签、相同返回路径；仅替换当前资源内容。
- 06：管理入口必须是“进入提示词管理”。
- 07：API Key 只能用掩码，不得生成任何看似真实的 token。
- 08–10：固定“资源列表—详情—应用分配”三栏；选择状态和右侧开关必须一致。
- 11：仅使用项目决策类安全示例，不出现姓名、关系、账号或个人经历。

## 4. 高保真自检提示词

```text
你是 FyAgent v3 的产品设计审查员。对比：
1. 产品讨论和线框事实；
2. 已确认的高保真视觉基线；
3. 当前页面候选图。

仅输出以下内容：
- Blocking：会导致错误实现的信息架构、入口、状态或文案问题；
- Major：明显破坏跨页一致性或可用性的问题；
- Minor：可在开发中顺手修正的视觉细节；
- Verdict：REGENERATE / ACCEPT_AS_DESIGN_CANDIDATE。

检查重点：左侧导航、active 状态、返回路径、管理入口、搜索与主动作位置、列表/详情/分配关系、开关状态一致性、中文可读性、隐私与密钥安全。
不要把没有运行态证据的图片评价为“实现通过”。
```

## 5. 设计通过后的 A-to-A 协作包

### 5.1 统一输入

所有 Agent 必须先读取：

1. 产品讨论文档；
2. 10 页线框；
3. 本目录 11 张高保真图；
4. 当前分支的现有前端代码、路由和组件；
5. 项目规范与本任务的验收清单。

任何新判断都要标记它来自 `discussion / wireframe / high_fidelity / current_code / inference` 中的哪一层。

### 5.2 建议分工

| 参与者 | 责任 | 主要产物 | 禁止越界 |
|---|---|---|---|
| Grok | 后端、组件与研究；挑战不必要的抽象和低价值测试 | 代码/研究、复杂度审查、验证输出 | 不修改视觉基线，不宣称最终验收 |
| Gemini | 视觉与交互实现/审查，维护跨页一致性、文案和状态覆盖 | 责任文件、问题清单、运行证据 | 不覆盖他人责任文件，不把图片当运行态 |
| Codex | 最终负责人：拆分、整合、冲突处理、测试、运行态证据和交付口径 | 最终分支、测试记录、截图、结论 | 不用单一 Agent 的完成声明替代验证 |

所有新 Codex 任务固定使用 `gpt-5.6-sol / max`。Gemini 使用已真实 probe 的 `antigravity/gemini-3.7-flash-high`。用户请求的 `grok-4.7/max` 当前不可用，执行侧透明使用最新可用 `vibekey/grok-4.6/high`，并持续保留未满足缺口；不得静默替换或伪称 4.7 已执行。

### 5.3 给实现 Agent 的任务提示词

```text
任务：实现 FyAgent 前端交互重构 v3 的指定页面。

事实优先级：产品讨论 > 已确认决策 > 高保真图中的交互位置 > 当前代码细节。
高保真图是设计候选，不是可直接复制的运行态证明。

你的责任范围：{owned_files_or_surfaces}
输入页面：{screen_ids}
验收：{commands_and_runtime_checks}

要求：
1. 先说明现有代码与目标页面的差异；
2. 只修改责任范围内的文件，不回滚其他 Agent 的改动；
3. 保留现有主题 token，优先复用现有组件；
4. 覆盖 loading、empty、success、error、disabled、selected 等与页面相关的状态；
5. 每个完成声明必须附文件、验证命令和实际结果；
6. 返回固定结构：结论 / 变更 / 证据 / 边界 / 下一步。
```

### 5.4 给审查 Agent 的任务提示词

```text
独立审查 FyAgent v3 指定页面，不修改代码。

比较对象：高保真候选、产品讨论、线框、当前实现与运行态截图。
按 Blocking / Major / Minor 输出；每条必须包含页面、位置、预期、实际和证据。
区分 code_audit、runtime_screenshot 和 pixel_diff；没有对应证据时不得升级结论。
```

### 5.5 给最终整合 Agent 的任务提示词

```text
你是最终负责人。合并 Grok 的实现与 Gemini 的审查结论，保留来源和责任边界。

顺序：
1. 验证各自交付文件与命令结果；
2. 解决冲突和 stale/contradicted 结论；
3. 运行 lint/type-check/test/build；
4. 启动本地运行态，覆盖关键状态并截图；
5. 若要求 1:1，针对冻结页面执行 pixel diff；
6. 输出通过项、未通过项、风险和下一步。

不得用代码审查替代运行态，也不得把候选图、合并、发布或生产互相混称。
```

## 6. 阶段门禁与完成定义

| 阶段 | 通过条件 | 当前状态 |
|---|---|---|
| G0 事实基线 | 讨论、线框、当前实现边界清楚 | 已完成 |
| G1 视觉方向 | 代表稿获得人类确认 | 已完成 |
| G2 完整原型 | 11 张候选与评审材料齐全 | 已完成 |
| G3 细节评审 | Blocking 反馈清零，页面冻结 | 已完成（人类批准 11 张图） |
| G4 开发规划 | 文件责任、顺序、模型/tier/成本获批 | 计划已完成，待一次最终批准 |
| G5 代码实现 | 指定页面和状态完成，基础检查通过 | 未开始 |
| G6 运行验收 | 本地运行态截图与关键交互证据通过 | 未开始 |
| G7 严格还原 | 需要时完成 pixel diff 并达到约定阈值 | 未开始 |
| G8 交付 | 提交、推送、合并、发布分别获授权并验证 | 未开始 |
