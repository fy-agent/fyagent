# FyAgent v0.4.11

This is a fix release after 0.4.10. It covers the notice after installation, one-click install on command-line tool cards, the OpenCode location text on Windows, a Gemini configuration file that fails to parse, and the instructions for when an unsigned Windows installer is blocked. This release also moves the base to CC Switch 4.0.4 and integrates aggregation and account quota.

## Additions and migration

- **Base moved to CC Switch 4.0.4.** The FyAgent base is moved to upstream CC Switch 4.0.4. Switching a Claude provider replaces only the fields that provider manages. Keys the user added stay in the local config and do not enter shared snippets. A failed Codex switch rolls back the config snippets and commits them when the next startup finishes the remaining work. Deleting an unused Codex overlay member also removes it from the overlay list. The hang in the Windows backend tests is fixed.
- **Aggregation entry and account quota.** The CC Switch 4.0.4 aggregation entry is integrated. The account page can view account quota and refresh it manually. Signing in again with the same account replaces the old credentials. The account page shows only a real software connection as "connected", and the page header shows one priority status.
- **Interface gaps left out of this release.** Pi, Mcode, and the remaining interface gaps such as Usage and Sessions are not in this release, and this release does not claim that all 4.0.4 interface capabilities are aligned.

## Fixes

- **Post-install notice.** After one-click install hands off to the vendor installer window, the closing notice was still given as "handed off to the vendor window" even when a later status refresh had already confirmed the install, so the card stayed on "The official installer window is open. Refresh the install status after you finish." When the latest install status is already "installed", it now shows "Operation completed." When the install is not yet confirmed, the original sentence stays. Only this sentence was changed. The card layout was not touched.
- **One-click install when status is unknown.** For command-line tools such as Grok Build and Claude Code, the install status can be "status unknown" in cases such as Windows ARM64, while the backend still allows installation. Previously "One-click install" appeared only for "not installed", so these cards had no install entry. "One-click install" is now shown when installation is allowed and either the app is not yet installed, or the status is unknown and the source is a command-line tool (`cli_tooling`). "Status unknown" on a desktop app does not gain this button from this change.
- **Blocked unsigned Windows installer.** The installer currently has no Authenticode signature, and the signature status on the Release page is `NotSigned`. The Chinese, English, and Japanese installation guides add "When the Windows installer is blocked", and the FAQ in each of the three READMEs adds a matching entry. The Japanese installation guide already had this page; this change only adds this section. The documented order is verify first, then allow: check the SHA-256 with PowerShell `Get-FileHash`, and `gh attestation verify` can also be used to view the build attestation; when SmartScreen shows "Windows protected your PC", use "More info" and "Run anyway", then confirm in User Account Control; if file Properties shows "Unblock", check it; Smart App Control judges in the cloud first, blocks only when it cannot confirm safety and there is no valid signature, cannot allow a single app on its own, and a recent Windows update can turn it back on without resetting the system; for an antivirus false positive, compare the hash first, exclude only that one file, and the false positive can also be submitted to Microsoft. Only 6 documents were changed.
- **OpenCode Windows install location.** The current-user location label used to read `%LOCALAPPDATA%\Programs\OpenCode`. The official NSIS installer actually installs to `%LOCALAPPDATA%\Programs\@opencodedesktop` (2.x), or `@opencode-aidesktop` (1.x, package name `@opencode-ai/desktop`). When it is not installed yet, the default shown is `@opencodedesktop`, because one-click install fetches OpenCode 2.x. In the windows-x64 log from the fork installer smoke, OpenCode 2.0.24 landed in `@opencodedesktop`. When it is already installed, the label shows the name of the directory that contains the exe. Both of the names above are recognized, case-insensitively; if neither matches, it still shows `OpenCode`. The copy for QoderWork, TRAE, WorkBuddy, macOS, and "all users" was not changed. Detection and the install process were not changed.
- **Gemini settings.json parse failure.** When `~/.gemini/settings.json` fails to parse (for example comments were written in by hand, or the file was only half written), switching the Gemini provider or authentication method used to treat it as an empty object `{}`, rebuild it, and write it back, which dropped the user's existing MCP servers (`mcpServers`) and other settings. A parse failure now stops, writes no files, and returns `gemini.validation.settings_parse_failed`; the JSON has to be fixed first. Creating the directory, and writing `.env`, settings, the backup, and undo, all come after a successful parse. Only a JSON parse error is replaced by this message. Other errors, such as reading or writing files, are still returned the same way as before. For a file that parses: when `config` is an object, it is merged into the existing settings and fields such as `mcpServers` are kept; when `config` is null or missing, the original file is kept; when the file did not exist, it is still created. An empty file and a whitespace-only file used to count as `{}` and are now treated as a parse failure as well. JSON with comments is not accepted.
