# FyAgent v0.4.6

Compared with 0.4.5, this update adds a practical workspace for customer projects,
extends subscription reuse to OpenCode, and simplifies everyday configuration.

## Highlights

- **A workspace for each customer project.** Keep goals, instructions, model and
  tool references separate by project, then archive completed work.
- **Reusable delivery kits.** Preview, import, bind and export starter kits for
  weekly business reports, knowledge support and business queries. The weekly
  report kit includes local examples; connecting a real customer system remains
  a separate setup step.
- **Checks and handover in one place.** Record preparation, verification and
  outstanding work, then export a handover document. Changes to project inputs
  make previous checks require review while preserving their history.
- **Subscription reuse for OpenCode.** Extend the existing Claude Code, Codex
  and Grok Build support with OpenCode binding and restoration. External edits
  are checked before configuration is restored.
- **Clearer everyday actions.** Consolidate MCP and Skills actions, reveal
  installation details on demand, simplify login messages, and reorganize the
  Chinese, English and Japanese manuals by current product feature.

## Fixes

- Restore or disconnect unchanged subscription bindings carried over from
  0.4.5, while protecting configuration edited after binding.
- Preserve each app's retry and timeout settings when stopping local forwarding
  or saving an automatically selected port.
- Retain existing per-app model metadata and ordering when updating a shared
  provider.
- Keep a reply and its following tool calls in the same turn, preserving
  message boundaries and meaningful reasoning text. Ignore empty reasoning
  updates without disrupting normal text output.
- Improve Grok native Responses compatibility for tool schemas, agent messages,
  model selection and completed integer tool arguments. Preserve original
  numeric values and streaming event metadata during response conversion.
- Do not confirm an assignment when its result is missing.
- Do not preselect every Agent when creating an MCP entry.
- Improve exact OpenCode provider selection, configuration reading and recovery.
- Keep Health checks read-only and avoid false drift reports for valid managed
  subscription routes.
- Restore search focus after clearing and correct oversized first-use icons.
- Preserve upgrade data, project drafts and kit versions, and correct the macOS
  notarization ticket processing order.

## Usage notes

FyAgent must remain running for local subscription forwarding. Model access and
quota depend on the account and upstream service. Saving a login and connecting
it to an Agent remain separate actions.

Publishing project context files and preparing an isolated Codex project
directory currently require macOS; these two operations are unavailable on
Windows. Starter kits do not automatically connect customer databases or
knowledge bases.
