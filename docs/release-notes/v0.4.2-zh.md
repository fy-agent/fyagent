# FyAgent v0.4.2

> [!IMPORTANT]
> FyAgent 仍在积极开发中。升级前请备份重要配置，并先阅读下方的信任与校验边界。
>
> v0.4.2 的发布合同要求恰好 8 个非空附件：4 个安装包、3 份发布证据 JSON，以及
> 1 个 Sigstore bundle。工作流会在发布前校验该集合。本文本身不声称已经完成
> 独立的发布后再下载复核。

> [!WARNING]
> 不要从 Release 标题或文件名推断 Windows 安装器的签名状态。正式工作流会根据
> 已发布的 `signing-status.json` 在说明末尾附加有证据支持的签名表。
>
> 如果某行报告 `NotSigned`，应预期 Windows SmartScreen 发出警告，且不要把该
> 文件当作 Authenticode 已签名。如果报告已验证签名，请在附加表中确认发布者
> 和时间戳状态，再检查 `signing-status.json` 中的签名和时间戳证书证据。同时
> 核对 SHA-256、源码 SHA 和 attestation。不要关闭 SmartScreen，也不要削弱
> 组织管理的安全策略。

## 主要变化

- **macOS Developer ID 与一次公证：** GitHub Actions 使用
  `Developer ID Application: William Wang (HY446996QX)` 签署 Universal 应用，
  然后只把已签名的 DMG 提交 Apple 公证。助手不带 `--wait` 提交，并轮询
  `notarytool info`，直到 Apple 接受或拒绝这一次提交，再用同一张票据装订 DMG
  和应用；ZIP 内含该已装订应用。这样不再串行等待两次公证，也不会把
  `notarytool wait --timeout` 的退出码 124 当成拒绝。
- **V2 设置体验：** Skill 与 MCP 操作保留在标题行；Agent 详情展示产品简介；
  Models 会对显式 Claude `/v1` 路径发出警告，并在保存前探测草稿服务 URL。
- **安装器与 CI：** Codex Desktop 不再额外重读 package hash。正式 `sourceSha`
  是标签指向的提交，而不是当时的 `main` HEAD。CI/Release 按 `Cargo.lock` 缓存
  `~/.cargo/registry` 与 `~/.cargo/git`。
- **0.4.0 的 V2 桌面壳与目录** 仍是当前交付：Agent 目录、Models、Skills、MCP、
  Prompts 和 Memory。
- **已交付平台：** 正式安装包为 Windows（x64 与 ARM64 NSIS）和 macOS Universal
  （DMG 与 ZIP）。本机开发检查不能替代这些安装包。

## 下载与信任说明

### Windows

按机器架构选择安装程序：

```text
FyAgent-0.4.2-Windows-x64-setup.exe
FyAgent-0.4.2-Windows-arm64-setup.exe
```

阅读本说明末尾的 **Windows installer signing status** 表，并在安装前核对对应
的 `signing-status.json`、SHA-256、源码 SHA 和 attestation。

### macOS

选择 DMG 或 ZIP；两者都包含 Universal 应用：

```text
FyAgent-0.4.2-macOS.dmg
FyAgent-0.4.2-macOS.zip
```

该 Universal 应用使用 Apple Developer ID 签名，并经过 Apple 公证。DMG 容器
本身也已签名、公证并装订。打开前请核对具体 Release 的 SHA-256、源码 SHA 和
attestation。如果 Gatekeeper 仍拦截首次启动，请在核对发布证据后，仅使用
**系统设置 → 隐私与安全性 → 仍要打开**。不要关闭 Gatekeeper，也不要移除
quarantine 元数据。

## 精确的 Release 附件合同

正式 Release 必须恰好包含以下 4 个安装包：

```text
FyAgent-0.4.2-macOS.dmg
FyAgent-0.4.2-macOS.zip
FyAgent-0.4.2-Windows-x64-setup.exe
FyAgent-0.4.2-Windows-arm64-setup.exe
```

还必须恰好包含以下 4 个证据附件：

```text
download-manifest.json
build-metadata.json
signing-status.json
artifact-attestation.sigstore.json
```

合计 8 个附件。attestation 有 7 个 subject：4 个安装包以及
`download-manifest.json`、`build-metadata.json` 和 `signing-status.json`。
复制出的 Sigstore bundle 是第 8 个附件，且不对自己做 attestation。缺失、
重复、改名、空文件、过期或多余附件都会阻止发布。

## 兼容性与升级说明

- 数据库 schema 版本为 19。现有 FyAgent 数据库会在首次启动时向前迁移。升级前
  请备份 `~/.fyagent`。
- 现有供应商、设置、Skills、备份、`fyagent://v1/import` 以及第三方 `/v1`
  合同仍由当前实现拥有。
- 早于本版本、且操作系统不在这对已交付平台内的 0.3.x / 0.4.0 安装包，不是
  受支持的升级路径。
- 已知的 v0.3.0 MSI 产品仍会在写入 NSIS 载荷前被同步移除；意外迁移结果会中止，
  而不是继续半替换安装。

平台安装步骤见
[安装说明](https://github.com/fy-agent/fyagent/blob/v0.4.2/docs/user-manual/zh/1-getting-started/1.2-installation.md)。

## 已知校验与安全边界

- **本次交付未运行 Windows HIL。** 现有证据覆盖可执行合同、可移植测试、
  Windows 目标编译、原生 x64/ARM64 构建与打包、签名或未签名证明、精确资产
  校验和审查。它不证明真实 Windows 10/11 x64 或 ARM64 机器上的安装/卸载、
  Explorer/UAC token、WebView2 用户数据路径、注册表、PackageManager file-URI、
  有效 ACL 执行或拒绝变更、终端清理或孤儿恢复。
- 当前用户 helper 不是受保护进程。已经以同一 Shell 用户运行的代码，可以在该
  用户现有 PackageManager 权限内尝试内存、句柄或进程操作。
- NSIS 进程查找是时点安全检查，不是文件系统变更前对新进程启动的原子互锁。
  安装程序从不强制终止 FyAgent 或其 helper。
- `NotSigned` 的 Windows 结果可能触发 SmartScreen 警告。SHA-256、源码 SHA
  绑定和 attestation 不能替代 Authenticode 发布者信任。
- macOS Developer ID 签名和 Apple 公证由 Release 工作流产生。本地检查不能
  证明已发布产物已经签名或公证。
- 本 Release 不声称独立的发布后再下载复核、管理员强制的仓库规则集，或单独的
  Main Provenance attestation。
