# FyAgent v0.4.15

These notes are release preparation. They are not a published GitHub Release. v0.4.10 remains Latest and v0.4.14 remains the prerelease. Do not tag this commit `v0.4.15` while Windows `signing-status.json` still has `mode` `unsigned` and `signature.status` `NotSigned`. The current formal workflow publishes a stable tag as Latest.

## Changes

- **First install.** The guide states what each step asks and what it installs. External installer prompts that were not recorded stay marked as not yet evidenced (#406).
- **Recommended installs.** Labels containing alpha, beta, preview, nightly, or rc stay out of the recommended list (#406).
- **Retired guidance.** zen-gate 1.8.0 removed its own free lane. OpenCode updates with `/update`. From qwen-code 0.25.1, `QWEN.md` and `AGENTS.md` in the parent directory are no longer read (#406).
- **Models.** With no previous visible target, Models opens on Claude Code. An existing visible target stays selected (#390).
- **WorkBuddy.** WorkBuddy has its own subscription binding and internal chat route. An unavailable account fails closed, and an in-stream failure is not treated as a normal end (#375, #378).

## Fixes

- **Accounts.** A saved login, a connected app, a required restart, and an unavailable official model list are separate states. The result area no longer pushes the account controls down the page (#407).
- **Package preparation.** Download, checksum, parse, permission, and disk failures are recorded as different stages instead of one disk-or-permission message (#407). The log line goes to the local `fyagent.log` and does not include a user name or token.

## Signing

The Certum SimplySign adapter and the public identity draft are in the repository (#405). Formal signing still requires `FYAGENT_WINDOWS_SIGNING_MODE=provider`, and the signing job runs adapter bytes from an Actions secret rather than the checked-out script path. This preparation does not change that variable and does not publish installers.

## Verification scope

Merge-queue CI covered frontend, repository contracts, and Windows/macOS backend after #405, #406, and #407, including Windows x64 and arm64 native contracts for #407. Install, upgrade, uninstall, and launch were not run. `signtool verify /pa /all /v /tw` was not run on a clean Windows machine. The macOS installer was not rechecked here with `codesign` or `stapler`.
