# FyAgent v0.4.0

> [!IMPORTANT]
> FyAgent 仍在持续开发。升级前请备份重要配置，并在安装前阅读下面的可信度说明。
>
> v0.4.0 的发布合同要求恰好 8 个非空附件：4 个安装包、3 份发布证据 JSON，以及
> 1 个 Sigstore bundle。工作流会在发布前核对该集合。本文本身不声称已经完成
> 独立的发布后再下载复核。

> [!WARNING]
> 不要从 Release 标题或文件名推断 Windows 安装包已经签名。正式工作流会根据已发布的
> `signing-status.json`，在说明末尾追加有证据的签名表。
>
> 如果某一行是 `NotSigned`，Windows SmartScreen 可能会警告，请不要把它当成
> Authenticode 已签名。如果报告为已验证签名，请核对该表中的发布者和时间戳状态，
> 并检查 `signing-status.json` 中的证书证据。同时核验 SHA-256、源 SHA 和
> attestation。不要关闭 SmartScreen，也不要削弱组织安全策略。

## 主要变化

- **V2 桌面界面：** 正式界面是本地控制中心，包含 Agent 目录、模型、Skills、MCP、
  提示词、记忆六个主页面。遗留 V1 渲染器不是当前发布壳层。
- **Agent 目录 v4：** QoderWork CN、TRAE Work CN、WorkBuddy、Grok Build、Codex、
  Claude Code、OpenCode 共用一份产品目录。详情页提供官方链接和直接能力跳转，
  不会冒充各产品自己的原生设置界面。
- **按产品合同管理模型：** WorkBuddy 与 OpenCode 使用专用模型配置；Claude Code、
  Codex、Grok Build 保留有边界的 Provider 快速设置；QoderWork CN 明确不支持
  第三方模型配置；TRAE Work CN 只观察厂商状态，不会把自定义模型写入 TRAE sqlite。
- **Skill 市场：** Skills 发现页按官方分类分页浏览 Skill Hub，从「详情」阅读全文，
  安装前确认目标应用。此路径不包含 GitHub 仓库浏览。
- **MCP 发现：** 精选目录（含国内连接器）区分发现、配置和安装。写入 WorkBuddy
  连接器后，界面会提示在 WorkBuddy 内完成信任。
- **提示词与记忆：** 提示词覆盖现有原生 Prompt 应用；记忆管理当前 OpenClaw /
  Hermes 长期资源。浏览器预览仍是 native-only，不会写入业务种子数据。
- **发布平台：** 正式安装包是 Windows（x64 / ARM64 NSIS）和 macOS Universal
  （DMG / ZIP）。当前宿主上的开发检查不能替代这些安装包。

## 下载与可信度

### Windows

请选择与机器架构匹配的安装程序：

```text
FyAgent-0.4.0-Windows-x64-setup.exe
FyAgent-0.4.0-Windows-arm64-setup.exe
```

阅读本说明末尾的 **Windows installer signing status** 表，并在安装前核验
`signing-status.json`、SHA-256、源 SHA 和 attestation。

### macOS

DMG 与 ZIP 都包含 Universal 应用：

```text
FyAgent-0.4.0-macOS.dmg
FyAgent-0.4.0-macOS.zip
```

该 Universal 应用使用无证书身份的 ad-hoc 签名，并在打包前完成校验。它不是
Apple Developer ID 签名，也未经公证。DMG 容器本身未签名。因此 Gatekeeper
可能阻止首次打开。请先核验 Release 证据，再在 **系统设置 → 隐私与安全性 →
仍要打开** 中放行。不要关闭 Gatekeeper，也不要移除隔离属性。

## 附件合同

正式 Release 必须恰好包含这 4 个安装包：

```text
FyAgent-0.4.0-macOS.dmg
FyAgent-0.4.0-macOS.zip
FyAgent-0.4.0-Windows-x64-setup.exe
FyAgent-0.4.0-Windows-arm64-setup.exe
```

以及这 4 个证据附件：

```text
download-manifest.json
build-metadata.json
signing-status.json
artifact-attestation.sigstore.json
```

合计 8 个附件。attestation 有 7 个主体：4 个安装包加上
`download-manifest.json`、`build-metadata.json` 和 `signing-status.json`。
复制出的 Sigstore bundle 是第 8 个附件，不对自己做证明。缺失、重复、改名、
空文件、过期或多余附件都会阻止发布。

## 兼容与升级

- 数据库 schema 版本为 19。已有 FyAgent 数据库会在首次启动时向前迁移。升级前请备份
  `~/.fyagent`。
- 现有供应商、设置、Skills、备份、`fyagent://v1/import` 以及第三方 `/v1` 合同
  仍由其当前实现负责。
- 更早 0.3.x Release 中、不属于这一对已发布系统的安装包，不是本版本的一部分，
  也不是受支持的升级路径。
- 已知的 v0.3.0 MSI 产品仍会在写入新的 NSIS 载荷前同步移除；异常迁移结果会中止，
  而不是继续半替换安装。

平台安装步骤见
[安装说明](https://github.com/fy-agent/fyagent/blob/v0.4.0/docs/user-manual/zh/1-getting-started/1.2-installation.md)。

## 已知验证与安全边界

- **本次交付未运行 Windows HIL。** 现有证据覆盖可执行合同、可移植测试、
  Windows 目标编译、原生 x64/ARM64 构建与打包、签名或未签名证明、精确资产核验
  和评审。它不能证明真实 Windows 10/11 x64 或 ARM64 机器上的安装/卸载行为、
  Explorer/UAC token 处理、WebView2 用户数据路径、注册表行为、PackageManager
  file-URI 行为、有效 ACL 执行或拒绝、终端清理或孤儿恢复。
- 当前用户 helper 不是受保护进程。已经以同一 Shell 用户运行的代码，可以在该用户
  既有 PackageManager 权限内尝试内存、句柄或进程操作。
- NSIS 进程查找是时点安全检查，不能原子阻止文件系统变更前的新进程启动。
  安装程序不会强制结束 FyAgent 或其 helper。
- `NotSigned` 的 Windows 结果可能触发 SmartScreen 警告。SHA-256、源 SHA 绑定和
  attestation 不能替代 Authenticode 发布者信任。
- macOS 应用只有无身份的 ad-hoc 签名；DMG 未签名，两者都不是 Developer ID
  签名，也未经公证。
- 本次 Release 不声称独立的发布后再下载核验、管理员强制的仓库规则集，或单独的
  Main Provenance attestation。
