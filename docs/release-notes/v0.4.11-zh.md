# FyAgent v0.4.11

这是 0.4.10 之后的修复版本，处理装完后的提示、命令行工具卡片上的一键安装、OpenCode 在 Windows 上的位置文字、Gemini 配置文件解析失败，以及未签名 Windows 安装包被拦截时的说明。这一版还把底座迁到 CC Switch 4.0.4，并接入聚合和账号额度。

## 新增与迁移

- **底座迁到 CC Switch 4.0.4**：FyAgent 底座迁到上游 CC Switch 4.0.4。切换 Claude 供应商时只替换供应商自己管的字段，用户自己加的键留在本机配置里，不进共享片段。Codex 切换失败会回滚配置片段，下次启动补完时再提交。删除没在用的 Codex 叠加成员时同步移出叠加名单。修复了 Windows 上后端测试卡死。
- **聚合入口与账号额度**：接入 CC Switch 4.0.4 的聚合入口。账号页可以查看账号额度并手动刷新。同一个账号重新登录时替换旧凭据。账号页只把真实软件连接显示为「已连接」，页头显示一条优先状态。
- **未纳入这一版的界面**：Pi、Mcode 以及 Usage、Sessions 等其余界面差距不在这一版，没有宣称全部 4.0.4 界面能力已对齐。

## 修复

- **装完后的提示**：一键安装交给厂商安装窗口之后，即使后面的状态刷新已经确认装好，结束时仍按「交给了厂商窗口」给提示，卡片就停在「官方安装窗口已打开。完成安装后请刷新安装状态。」。最新安装状态已经是「已安装」时，现在显示「操作已完成。」。还没确认装好时，原来那句保留。只改了这一句，卡片布局没动。
- **状态未知时的一键安装**：Grok Build、Claude Code 这类命令行工具，在 Windows ARM64 等情况里，安装状态可能是「状态未知」，后端仍允许安装。以前要「未安装」才出现「一键安装」，这种卡片上没有安装入口。现在在允许安装，并且尚未安装，或者状态未知且来源是命令行工具（`cli_tooling`）时，显示「一键安装」。桌面应用的「状态未知」不会因此出现这个按钮。
- **Windows 未签名安装包被拦住**：安装包目前没有 Authenticode 签名，Release 页的签名状态是 `NotSigned`。中文、英文、日文安装说明新增「Windows 安装包被拦截时」，三份 README 的常见问题加了对应条目。日文安装说明原来就有这一页，这次只加了这一节。写明的顺序是先校验、再放行：用 PowerShell `Get-FileHash` 核对 SHA-256，也可以用 `gh attestation verify` 看构建证明；SmartScreen 出现「Windows 已保护你的电脑」时，走「更多信息」「仍要运行」，再在用户账户控制里确认；文件属性里出现「解除锁定」再勾上；智能应用控制先由云端判断，确认不了安全且没有有效签名时才拦截，不能单独放行某一个应用，近期的 Windows 更新可以不重置系统就重新打开它；杀毒软件误报时先对哈希，只排除这一个文件，也可以向微软提交误报。只改了 6 个文档。
- **OpenCode 的 Windows 安装位置**：当前用户的位置标签以前写 `%LOCALAPPDATA%\Programs\OpenCode`。官方 NSIS 安装包实际装到 `%LOCALAPPDATA%\Programs\@opencodedesktop`（2.x），或 `@opencode-aidesktop`（1.x，包名 `@opencode-ai/desktop`）。还没安装时，默认显示 `@opencodedesktop`，因为一键安装拿到的是 OpenCode 2.x。分叉安装冒烟的 windows-x64 日志里，OpenCode 2.0.24 落在 `@opencodedesktop`。已经安装时，按 exe 所在目录名显示，上面两个名字都认，不区分大小写；对不上就仍显示 `OpenCode`。QoderWork、TRAE、WorkBuddy、macOS，以及「所有用户」的文案没改。探测和安装过程没改。
- **Gemini 的 settings.json 解析失败**：`~/.gemini/settings.json` 解析失败时（例如手写了注释，或文件只写了一半），切换 Gemini 供应商或认证方式以前会把它当成空对象 `{}` 重建写回，用户原有的 MCP 服务器（`mcpServers`）等设置会丢。现在解析失败就停，不写任何文件，返回 `gemini.validation.settings_parse_failed`，需要先把 JSON 改好。建目录，以及写 `.env`、settings、备份和 undo，都排在解析成功之后。只有 JSON 解析错误换成这条提示，读写文件之类的其他错误仍按原来的方式返回。能解析的文件：`config` 是对象时并入现有设置，保留 `mcpServers` 等字段；`config` 为 null 或缺失时保留原文件；文件本来没有，仍会新建。空文件和纯空白以前当成 `{}`，现在也按解析失败处理。不做带注释 JSON 的兼容。
