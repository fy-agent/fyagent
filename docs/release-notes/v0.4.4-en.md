# FyAgent v0.4.4

FyAgent v0.4.4 brings account management, Claude Code CLI installation, and
reversible configuration changes into the desktop control center. It also
consolidates the production renderer and improves startup, navigation, themes,
scrolling, and dialog interactions.

## Highlights

- **Accounts and software connections in one place.** Manage OpenAI and xAI
  accounts through backend-owned login sessions. Account storage, software
  connection, and the current model-request source are shown as distinct states.
- **Explicit, recoverable configuration changes.** Review affected files and
  backup locations before supported account-connection changes. Codex and
  OpenCode Desktop projection keep credential purposes separate and verify files
  after writing; pending restart is reported when live pickup is not established.
- **Claude Code CLI installation.** Install or update reviewed official npm
  packages using the shared mirror selection and ordinary-user execution
  boundary. Claude Code is CLI-only; other installation owners are not replaced.
- **A more consistent desktop experience.** Paired blue themes, native-backed
  appearance persistence, content-ready startup, persistent navigation, and
  responsive assignment panels share one production renderer.
- **Interaction and platform fixes.** Restored bounded scrolling and visible
  labels, corrected dialog return/focus behavior, fixed WorkBuddy discovery and
  Claude readiness, preserved OAuth URL parameters, and repaired Windows npm
  shim execution. Idle Codex Desktop no longer prompts for a needless restart.

## Upgrade and behavior notes

Account login saves a credential; connecting that account to software is a
separate confirmed action. For Codex, official connection can comment the
top-level `model_provider` selector; disconnect can restore it. Saved third-party
source changes preserve `auth.json` and unrelated configuration.

Backups and guarded recovery apply to supported file writers. They are not a
cross-file atomic transaction, and a failed operation can require a reread or
manual recovery. Appearance persistence is best-effort if the settings file
cannot be written. Keep independent backups of important configuration.

Installation success does not establish successful vendor login or inference.
Windows vendor-wizard handoff still requires later installation observation.
Grok native credential projection and macOS privileged `/Applications` commits
retain their existing production gates; packaging a helper does not enable them.

## Release artifacts

The formal workflow publishes these seven attachments only after native builds,
platform verification, signing/notarization as required, and attestation:

```text
FyAgent-0.4.4-macOS.dmg
FyAgent-0.4.4-Windows-x64-setup.exe
FyAgent-0.4.4-Windows-arm64-setup.exe
download-manifest.json
build-metadata.json
signing-status.json
artifact-attestation.sigstore.json
```

The DMG supports Apple Silicon and Intel Macs. Windows installers are built on
matching native x64 and ARM64 runners. The appended Windows signing disclosure
is generated from verified release metadata, not inferred from build success.
