# 2.2 Update tools and diagnose installation conflicts

When an update appears to succeed but the old version still runs, the usual cause is another installation earlier on PATH. FyAgent checks for this before and after updates.

## Update one or several tools

- Use the action on a card to update one tool.
- **Update all** processes the six managed tools one by one. Each tool has its own result, so one failure does not skip the remaining tools.
- Codex CLI participates in version and conflict detection but not install or update actions.

Before an update, FyAgent enumerates known installation locations. If it finds several copies, it shows their paths and versions and asks you to confirm. This avoids silently updating one copy while your terminal continues to use another.

## Diagnose all tools

**Diagnose all tools** checks Claude Code, Codex CLI, Gemini CLI, Grok Build, OpenCode, OpenClaw, and Hermes. Diagnosis reads locations and versions; it does not remove old files for you.

When there is a conflict, first determine which path your everyday terminal resolves. Do not choose a copy only because its path looks newer, and do not manually delete an unfamiliar system directory.

## Read the result

| Result | Meaning | Next step |
|---|---|---|
| Success | The command completed and the refreshed version matches the expected state | Run `--version` once in your working terminal |
| Partial success | Some tools in a batch completed and others did not | Read the final error line for each failed tool |
| Hard failure | The install or update command itself failed | Check the network, permissions, and package-manager output |
| Version unchanged | The command returned success but the old version still resolves | Review multiple locations and PATH order |
| Installed but not runnable | Files may exist, but the version command cannot start | Check the runtime, shell, and PATH |

After an update, FyAgent silently diagnoses that tool again. A clean result removes an old conflict message; remaining duplicates keep their path list visible.

## A practical troubleshooting order

1. Run the tool diagnostic in FyAgent.
2. In the terminal where you write code, run the tool's `--version` and path lookup command.
3. Compare that path with the locations shown by FyAgent.
4. Remove an unwanted copy through the package manager that installed it, then reopen the terminal.
5. Refresh the version in FyAgent and make one real test call.
