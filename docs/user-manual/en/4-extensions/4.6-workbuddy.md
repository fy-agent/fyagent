# 4.6 Configure WorkBuddy models

WorkBuddy has its own entry in the top-level app switcher, immediately after Codex. This page reads and updates the current user's `~/.workbuddy/models.json`; it does not turn WorkBuddy into a Provider, MCP server, or Skill.

## Connect and fetch models

1. Switch to WorkBuddy.
2. Enter the Base URL. FyAgent derives the model-list endpoint, so the service base path is usually enough.
3. Enter the API Key. The eye button only changes input visibility; FyAgent never reads an existing key back from disk.
4. Enable **Allow no API Key** only when the service explicitly supports anonymous access.
5. Select **Fetch models**.

The Base URL must be an absolute HTTP(S) URL with a host and no user information, query, or fragment. A remote plain-HTTP address displays a clear-text transport warning. FyAgent accepts only same-origin redirects and never forwards the key to another site.

## Select and save

After a successful fetch, search the list, select individual models, or select and clear the current filtered results. If the response is valid but too long and is truncated, the warning remains until a later complete fetch succeeds. You can also enter model IDs manually, one per line.

On save, FyAgent updates `models.json` while preserving unrelated models, order, and unknown fields where possible. Existing model IDs are visible, but their API keys never enter the renderer.

If a target ID already exists, FyAgent lists the duplicate IDs and asks for a second confirmation. That confirmation applies only to the exact pending save and cannot be reused. If another process changes the file before confirmation, the save stops and refreshes the current state instead of overwriting the external change.

## Keys and backups

The API Key exists only in the current component memory, one Tauri request, and the protected configuration file. Leaving the WorkBuddy view clears the in-memory key. A save maintains `models.json.backup` in the same directory and uses completed same-directory replacement for both files.

When you update an existing model without supplying a new key, the page can offer to clear the old key. This option appears only when a selected target already exists; review the target list before enabling it.

## Error groups

| Group | Possible codes | What to check |
|---|---|---|
| URL and authentication | `WORKBUDDY_INVALID_URL`, `WORKBUDDY_API_KEY_REQUIRED` | Check the Base URL structure and whether anonymous access is really supported |
| Network and response | `WORKBUDDY_FETCH_HTTP_ERROR`, `WORKBUDDY_FETCH_TIMEOUT`, `WORKBUDDY_FETCH_REDIRECT_REJECTED`, `WORKBUDDY_FETCH_RESPONSE_TOO_LARGE`, `WORKBUDDY_FETCH_INVALID_SCHEMA` | Check service health, same-origin redirects, and the `/models` response shape |
| Reading configuration | `WORKBUDDY_CONFIG_READ_FAILED`, `WORKBUDDY_CONFIG_INVALID_JSON`, `WORKBUDDY_CONFIG_ROOT_NOT_ARRAY`, `WORKBUDDY_CONFIG_ROOT_UNSUPPORTED`, `WORKBUDDY_CONFIG_MODELS_NOT_ARRAY`, `WORKBUDDY_CONFIG_INVALID_ENTRY` | Back up the file and inspect its JSON structure; FyAgent does not repair malformed data automatically |
| Target models | `WORKBUDDY_CONFIG_NO_TARGET_MODELS`, `WORKBUDDY_CONFIG_DUPLICATE_TARGET`, `WORKBUDDY_CONFIG_EXISTING_TARGET` | Select at least one model and resolve duplicate or existing IDs |
| Concurrency and confirmation | `WORKBUDDY_CONFIG_CONCURRENT_MODIFICATION`, `WORKBUDDY_OVERWRITE_TOKEN_INVALID`, `WORKBUDDY_OVERWRITE_TOKEN_EXPIRED` | Refresh, review the new state, and start the save again |
| Write and internal failures | `WORKBUDDY_CONFIG_BACKUP_FAILED`, `WORKBUDDY_CONFIG_WRITE_FAILED`, `WORKBUDDY_INTERNAL_ERROR` | Check directory permissions and free space, while preserving the original file |

Errors expose only the status needed to act; they do not echo API keys, complete responses, or overwrite capabilities.
