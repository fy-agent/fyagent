# モデル管理

「模型管理」の「选择应用」で対象を選ぶか、上部の「一键配置主流大模型」「全端体检与克隆」から複数クライアントをまとめて管理できます。`QoderWork CN` と `TRAE Work CN` は公式モデル専用のため、第三者モデルは各アプリ内で設定してください。

## 単体クライアントの入力と保存

1. 設定名（表示される場合）、サービス URL、API Key、モデル ID を入力します。URL は HTTP(S) とし、キーは専用欄に入力します。
2. 「拉取模型」で取得するか、ID を手入力します。WorkBuddy、OpenCode、Oh My Pi（`omp`）は複数 ID を設定できます。保存予定の一覧を確認します。
3. 保存済みモデル横の「测速」（または「测试连通」）で接続を確認できます。テストは最小リクエストのみを送信し、HTTP 404 でも保存済みモデルを削除・変更しません。
4. 「保存并设为当前配置」または「保存并应用」を押し、対象ファイルとバックアップ案内を確認してから確定します。
5. 現在の設定を確認し、案内に従って対象ソフトウェアの更新表示、再起動、または新しいセッションの開始を行います（Codex 実行時は上部バナーでデーモン再起動やデスクトップ再起動を案内します）。

Claude Code の URL は、パス重複を避けるため通常は末尾の `/v1` を除きます。サービスの説明に従って確認してください。認証不要のローカルサービスには、表示される「不使用 API Key」を使います。Codex の WebSocket と画像生成拡張はサービスの互換性に合わせて選びます。

## 一括設定・クローン・キー更新・マイテンプレート

- **主要モデル一括設定**：内蔵プロバイダー（DeepSeek、Kimi、Zhipu GLM、Aliyun DashScope、Volcengine Ark、MiniMax、SiliconFlow、OpenRouter）または保存済みのカスタムテンプレートを選び、API Key を一度貼り付けて対象ソフトを選び、変更ファイルをプレビューしてから書き込みます。
- **全クライアント状態一覧**：6 クライアントのモデル・ドメイン・認証方式を一覧表示して並列接続テストでき、他クライアントへのクローン、同一ホストのキー一括更新、よく使う中継先のテンプレート保存（API Key は保存しません）に対応しています。
- **失敗時の隔離とロールバック**：書き込み前にバックアップを保存し、特定クライアントで失敗した場合はそのクライアントのみ元ファイルへ戻して明示し、失敗分だけ再試行できます。

## 変更されるファイル・項目と、決して変更しない範囲

| 対象ソフト       | 対象ファイル                                         | 更新する項目のみ                                                           | 決して変更しない項目                                                 |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| WorkBuddy        | `~/.workbuddy/models.json`                           | 選択モデルの URL、API Key、モデル ID                                       | 他のカスタムモデル、履歴、MCP、Skills、公式ログイン                  |
| Codex            | `~/.codex/config.toml`、`~/.codex/auth.json`         | 選択中のカスタムプロバイダー URL・プロトコル・モデル ID・`OPENAI_API_KEY`  | セッション履歴、`AGENTS.md`、MCP、Skills、無関係な設定セクション     |
| Claude Code      | `~/.claude/settings.json`、`~/.claude.json`          | `env` 内の `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL` | セッション履歴、`CLAUDE.md`、MCP、Skills、権限・その他の手動設定     |
| OpenCode         | `~/.config/opencode/opencode.json`                   | 指定カスタムプロバイダーの `baseURL`、`apiKey`、モデル一覧                 | 他のプロバイダー、UI 設定、MCP、その他のカスタム項目                 |
| Oh My Pi (`omp`) | `~/.omp/agent/models.yml`、`~/.omp/agent/config.yml` | 指定プロバイダーの URL、プロトコル、キー、既定モデル                       | YAML コメント、他のプロバイダー、未知項目、プライベートな `agent.db` |
| Grok Build       | `~/.grok/config.toml`                                | 指定モデルの URL、表示名、プロトコル、API Key                              | セッション履歴、プロンプト、MCP、Skills、その他の設定                |

**構造アップグレード前のバックアップとダウングレード保護**：ローカルデータベースのバージョンアップ前に自動で検証済みバックアップを作成します。古い FyAgent で新しいデータベースを開いた場合は、黙って破損させずアップグレードを促す案内を表示します。

## サブスクリプションを使う

「使用账号订阅（实验性）」で保存済みの ChatGPT または Grok アカウントを選び、対応モデル ID を選択・入力します。Grok の候補例が利用できるかはサービスの応答で確認します。

Codex は「保存 Codex 订阅配置」の後、「账号与认证」で接続先の変更をプレビューして確定します。他の対象は表示された適用ボタンでファイル変更を確認します。利用中は FyAgent をバックグラウンドで実行してください。完全に終了するとローカル転送が停止します。実際の利用可否と利用枠はサービスの応答に従います。

[アカウント](accounts.md) と [問題への対処](troubleshooting.md) も参照してください。
