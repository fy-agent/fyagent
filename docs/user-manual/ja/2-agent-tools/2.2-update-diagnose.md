# 2.2 ツールの更新とインストール競合の診断

更新が成功したように見えるのに古いバージョンが起動する場合、PATH の前方に別のインストールが残っていることがよくあります。FyAgent は更新の前後にその状態を確認します。設定から更新できるのは **Grok Build** だけです。

## Grok Build を更新する

- カードの操作から Grok Build を更新できます。
- 他の CLI カードは参照専用で、更新ボタンは出ません。
- Claude Desktop、Codex Desktop、OpenCode Desktop の更新は Agent ページで行い、設定の CLI 一覧では扱いません。

更新前に、FyAgent は既知のインストール元を確認します。Grok Build のコピーが複数ある場合は、各出所とバージョンを表示し、続行前に確認を求めます。画面にはローカルの絶対パスを出しません。

## 診断する

診断は Claude Code、Codex CLI、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes を確認します。場所の出所とバージョンを読むだけで、古いファイルを自動削除しません。

競合が見つかったら、まず普段のターミナルがどれを選んでいるかを確認してください。新しそうという理由だけで選ばず、見覚えのないシステムディレクトリを直接削除しないでください。

## 結果の読み方

| 結果 | 意味 | 次にすること |
|---|---|---|
| 成功 | 操作が完了し、再検出したバージョンが期待どおり | 作業用ターミナルでも `--version` を実行 |
| ハード失敗 | インストールまたは更新自体が完了していない | ネットワーク、権限、現在のユーザー環境を確認 |
| バージョン不変 | 処理は終わったが古いバージョンが解決される | 複数のインストール元を確認 |
| インストール済みだが実行不能 | ファイルはあってもバージョンコマンドが起動しない | ランタイム、shell、PATH を確認 |

更新後には、そのツールの競合診断がもう一度静かに実行されます。競合が解消していれば古い表示を消し、複数のコピーが残っていれば出所一覧を維持します。

## おすすめの切り分け順

1. FyAgent で対象ツールを診断します。
2. 実際に作業するターミナルで `--version` を実行します。
3. FyAgent が表示したインストール元と照合します。
4. 不要なコピーを、それを入れた公式手段から削除し、ターミナルを開き直します。
5. FyAgent でバージョンを更新し、最後に実際のリクエストを 1 回試します。
