# 2.2 ツールの更新とインストール競合の診断

更新が成功したように見えるのに古いバージョンが起動する場合、PATH の前方に別のインストールが残っていることがよくあります。FyAgent は更新の前後にその状態を確認します。

## 単体または一括で更新する

- カードの操作から 1 ツールだけ更新できます。
- 「すべて更新」は管理可能な 6 ツールを順番に処理します。結果はツールごとに独立しており、1 件の失敗で後続を止めません。
- Codex CLI はバージョンと競合の検出対象ですが、インストール・更新の対象ではありません。

更新前に、FyAgent は既知のインストール場所を列挙します。複数のコピーがある場合はパスとバージョンを表示し、続行前に確認を求めます。これにより、普段使っていないコピーだけを更新する事故を避けられます。

## 全ツールを診断する

「すべてのツールを診断」は Claude Code、Codex CLI、Gemini CLI、Grok Build、OpenCode、OpenClaw、Hermes を確認します。診断は場所とバージョンを読むだけで、古いファイルを自動削除しません。

競合が見つかったら、まず普段のターミナルがどのパスを選んでいるかを確認してください。パスが新しそうという理由だけで選ばず、見覚えのないシステムディレクトリを直接削除しないでください。

## 結果の読み方

| 結果 | 意味 | 次にすること |
|---|---|---|
| 成功 | コマンドが完了し、再検出したバージョンが期待どおり | 作業用ターミナルでも `--version` を実行 |
| 一部成功 | 一括操作の一部だけが完了 | 失敗した各ツールの最後のエラー行を確認 |
| ハード失敗 | インストールまたは更新コマンド自体が失敗 | ネットワーク、権限、パッケージマネージャー出力を確認 |
| バージョン不変 | 成功終了したが古いバージョンが解決される | 複数の場所と PATH の順序を確認 |
| インストール済みだが実行不能 | ファイルはあってもバージョンコマンドが起動しない | ランタイム、shell、PATH を確認 |

更新後には、そのツールの競合診断がもう一度静かに実行されます。競合が解消していれば古い表示を消し、複数のコピーが残っていればパス一覧を維持します。

## おすすめの切り分け順

1. FyAgent で対象ツールを診断します。
2. 実際に作業するターミナルで `--version` とパス確認コマンドを実行します。
3. FyAgent が表示したインストール場所と照合します。
4. 不要なコピーを、それを入れたパッケージマネージャーから削除し、ターミナルを開き直します。
5. FyAgent でバージョンを更新し、最後に実際のリクエストを 1 回試します。

WSL の場合はディストリビューション、shell、起動フラグも確認してください。Windows と WSL は別環境であり、片方へのインストールはもう片方には反映されません。
