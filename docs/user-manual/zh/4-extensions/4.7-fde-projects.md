# 客户项目与交付

“客户项目”面向需要到客户现场梳理业务、接入工具、验证效果并完成交接的 FDE。把每个客户的说明、资源引用、交付方法和检查记录放在同一个项目中，减少切换客户时重新找资料、复查配置和整理交接的工作。

本页描述当前仓库的 FDE 功能。正式安装包是否包含这些功能，以对应发布说明为准。

## 跑通一个经营周报项目

1. 打开“客户项目”，选择“新建项目”，填写客户归属和项目名称。
2. 在“项目准备”的工作说明中记录业务目标、数据口径、获准使用的资料和待确认事项，保存。每次保存保留前一个版本；修改失败时可以重新载入，文件不可用时按提示重新建立。
3. 从“项目资源”引用已有模型配置、MCP、提示词或 Skill。模型引用同时填写要检查的模型名称。账号引用只记录用途，不复制凭据。选择项目或添加引用不会自动启用其他软件的全局配置。
4. 切到“交付方案”，预览经营周报包，导入包库后选择“用作项目方案”。页面会标明当前项目使用的方案。运行内置样例，查看指标、来源行及负例的预期处理。经营周报的正常样例计算环比增长 20%、目标完成率 90%；缺字段、重复记录和零分母分别按包内规则处理。
5. 将本机样例检查保存到项目，再到“验证与交接”查看记录。检查已保存的配置；有明确模型绑定时，可检查其实际返回身份。模型请求通过只代表这次模型检查通过。
6. 实际接入客户系统后，按阶段补充操作人、范围和可核对依据。填写交接事项与负责人，预览后导出 Markdown 或 JSON。

三个工作区可以随时切换，不要求按固定顺序填写。切换客户或项目之前，先保存当前修改。

## 包与检查记录

内置包包括经营周报、知识客服和经营查询。经营周报具备本机可计算样例；知识客服和经营查询提供输入要求、方法、失败情形及交接起点，仍需自行连接获准的知识库或数据库。

交付包使用 `.fyagent-kit.json` 文件。导入前可预览；相同版本和内容可重复导入，相同版本内容不同会被拒绝。导入和绑定不会执行任意脚本、安装工具或带入秘密。自有包也可以从包库预览并导出。

| 阶段     | 用途                               |
| -------- | ---------------------------------- |
| 配置     | 核对本项目保存的引用和资料         |
| 认证     | 记录人工核对的认证依据             |
| 工具     | 保存指定模型检查或实际工具调用依据 |
| 样本     | 保留本机样例结果或真实业务样本依据 |
| 客户验收 | 由有权验收的人提供明确范围与依据   |

每个阶段独立记录。内置样例和接口成功不会自动变成客户验收。修改项目、绑定包或来源资源后，相关旧记录保留为“待复核”；撤销记录同样保留历史。短时在线检查还有有效期，需要重新检查。Skill 文件内容当前不能仅凭库中的版本证明一致，应核对实际文件。

## 项目工作目录

保存工作说明后，可以生成独立的 Codex 工作目录、只读配置与检查说明。复制目录，在 Codex 中选择该目录继续工作；按生成说明检查配置来源、认证和权限。FyAgent 不会自动启动 Agent，账号、MCP 和 Skill 需要按项目另行配置。

项目区分本地资料和配置作用域，不提供操作系统沙箱。归档项目保留只读资料；归档的客户可以在“管理客户”中恢复。项目数据与检查记录当前仅保存在本机；跨设备同步不会把这些本地记录当作可共享配置自动覆盖。

## 交接文件

导出前检查预览中的项目版本、包版本、结果来源、失败原因、负责人和未完成项。导出保留必要的检查摘要，排除凭据和内部文件路径。模型厂商、客户系统、部署环境和验收负责人仍需分别核实；交接文件记录已有证据，不代替现场操作或客户签收。
