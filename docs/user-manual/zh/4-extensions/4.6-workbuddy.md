# 4.6 WorkBuddy 模型配置

WorkBuddy 在顶部应用切换器里有独立入口，位于 Codex 之后。这个页面只负责读取和更新当前用户的 `~/.workbuddy/models.json`，不会把配置混进供应商、MCP 或 Skills。

## 连接并获取模型

1. 切换到 WorkBuddy。
2. 填写 Base URL。FyAgent 会补齐模型列表端点，因此一般填到服务的基础路径即可。
3. 填写 API Key。眼睛按钮只改变输入框是否可见，不会从磁盘回填密钥。
4. 只有服务明确允许匿名访问时，才打开“允许无 API Key”。
5. 点击“获取模型”。

Base URL 必须是带主机名的绝对 HTTP(S) 地址，不能包含用户名、密码、查询参数或片段。远程地址使用普通 HTTP 时，页面会给出明文传输警告。FyAgent 只接受同源跳转，不会把 API Key 带到另一个站点。

## 选择并保存

获取成功后，可以搜索模型、逐项勾选，或对当前筛选结果全选和清空。列表过长而被截断时，警告会一直保留，直到下一次完整获取成功。没有出现在远端列表里的模型，也可以按行手工填写 ID。

保存时，FyAgent 会把选中的模型写入 `models.json`，并尽量保留原有顺序、其他模型和未知字段。页面显示的已有模型来自本地文件，但不会把其中的 API Key 展示到前端。

如果目标模型已经存在，FyAgent 会列出重复的 ID 并要求二次确认。这个确认只对当前这次保存有效，不能复用。如果确认前文件被其他程序改过，保存会停止并刷新状态，避免覆盖外部改动。

## 密钥与备份

API Key 只存在于当前输入框、一次 Tauri 请求和受保护的配置文件中。离开 WorkBuddy 页面后，内存里的 Key 会被清空。保存时会在同一目录维护 `models.json.backup`；备份和主文件都在写入完成后再替换，降低中途损坏的风险。

当你更新一个已有模型但没有填写新 Key 时，可以选择是否清除它原来的 Key。这个选项只在确实命中已有模型时出现，请先确认影响范围。

## 常见错误怎么处理

| 类别 | 可能出现的错误码 | 处理方向 |
|---|---|---|
| 地址与鉴权 | `WORKBUDDY_INVALID_URL`、`WORKBUDDY_API_KEY_REQUIRED` | 检查 Base URL 结构；没有 Key 时确认服务是否真的允许匿名访问 |
| 网络与响应 | `WORKBUDDY_FETCH_HTTP_ERROR`、`WORKBUDDY_FETCH_TIMEOUT`、`WORKBUDDY_FETCH_REDIRECT_REJECTED`、`WORKBUDDY_FETCH_RESPONSE_TOO_LARGE`、`WORKBUDDY_FETCH_INVALID_SCHEMA` | 检查服务状态、同源跳转和 `/models` 返回格式 |
| 配置读取 | `WORKBUDDY_CONFIG_READ_FAILED`、`WORKBUDDY_CONFIG_INVALID_JSON`、`WORKBUDDY_CONFIG_ROOT_NOT_ARRAY`、`WORKBUDDY_CONFIG_ROOT_UNSUPPORTED`、`WORKBUDDY_CONFIG_MODELS_NOT_ARRAY`、`WORKBUDDY_CONFIG_INVALID_ENTRY` | 先备份文件，再用 JSON 工具检查结构；FyAgent 不会自动修复坏文件 |
| 目标模型 | `WORKBUDDY_CONFIG_NO_TARGET_MODELS`、`WORKBUDDY_CONFIG_DUPLICATE_TARGET`、`WORKBUDDY_CONFIG_EXISTING_TARGET` | 至少选择一个模型，并处理重复 ID 或已有模型确认 |
| 并发与确认 | `WORKBUDDY_CONFIG_CONCURRENT_MODIFICATION`、`WORKBUDDY_OVERWRITE_TOKEN_INVALID`、`WORKBUDDY_OVERWRITE_TOKEN_EXPIRED` | 刷新当前状态，重新检查选择后再保存 |
| 写入与内部错误 | `WORKBUDDY_CONFIG_BACKUP_FAILED`、`WORKBUDDY_CONFIG_WRITE_FAILED`、`WORKBUDDY_INTERNAL_ERROR` | 检查目录权限和磁盘空间；保留原文件后再重试 |

错误信息只会带必要的状态，不会回显 API Key、完整响应或覆盖确认凭据。
