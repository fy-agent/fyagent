# 2.2 升级工具并诊断安装冲突

工具“明明升级了却还是旧版本”，最常见的原因不是升级按钮失效，而是电脑里存在多个安装位置。FyAgent 会在升级前后检查这种情况。设置页里只有 **Grok Build** 可以升级。

## 升级 Grok Build

- Grok Build 有新版本时，可以从卡片直接升级。
- 其余 CLI 卡片只读，不会出现升级按钮。
- Claude Desktop、Codex Desktop、OpenCode Desktop 的更新走 Agent 页面，不走设置页 CLI。

升级前，FyAgent 会检查已知安装来源。如果 Grok Build 有多份安装，界面会列出各处来源和版本，请你确认后再继续。界面不显示本地绝对路径。

## 运行诊断

点击诊断后，FyAgent 会检查 Claude Code、Codex CLI、Gemini CLI、Grok Build、OpenCode、OpenClaw 和 Hermes。诊断只读取安装来源和版本，不会替你删除旧文件。

发现冲突后，先确认自己日常使用的终端实际命中了哪一处，再决定卸载哪一份。不要只按来源新旧猜测，也不要直接删除一个不认识的系统目录。

## 怎样理解结果

| 结果 | 意思 | 下一步 |
|---|---|---|
| 成功 | 操作完成，重新探测到的版本符合预期 | 在日常终端再跑一次 `--version` |
| 硬失败 | 安装或升级本身没有完成 | 检查网络、权限和当前用户环境 |
| 版本未变化 | 操作结束，但仍命中旧版本 | 查看多处安装来源 |
| 已安装但无法运行 | 可能已有文件，但版本命令启动失败 | 检查运行时、shell 与 PATH |

升级结束后，FyAgent 还会为该工具补做一次冲突诊断。没有冲突时会清除旧提示；仍有多份安装时会保留来源列表。

## 推荐的排查顺序

1. 在 FyAgent 中运行该工具的诊断。
2. 在你真正写代码的终端执行该工具的 `--version`。
3. 对比 FyAgent 列出的安装来源，确认当前命中项。
4. 通过对应的官方渠道卸载多余版本，再重新打开终端。
5. 回到 FyAgent 刷新版本，最后做一次实际调用。
