# 2.2 升级工具并诊断安装冲突

工具“明明升级了却还是旧版本”，最常见的原因不是升级按钮失效，而是电脑里存在多个安装位置，终端继续命中了旧的那个。FyAgent 会在升级前后检查这种情况。

## 升级一个或多个工具

- 单个工具有新版本时，可以从卡片直接升级。
- “全部升级”会逐个处理六个可管理工具。每个工具独立记录成败，一个失败不会跳过后面的工具。
- Codex CLI 参与版本和冲突探测，但不参加安装或升级。

升级前，FyAgent 会枚举已知安装位置。如果同一工具有多份安装，界面会先列出路径和版本，请你确认后再继续。这样可以避免在不知情的情况下只升级了其中一份。

## 运行全量诊断

点击“诊断全部工具”，FyAgent 会检查 Claude Code、Codex CLI、Gemini CLI、Grok Build、OpenCode、OpenClaw 和 Hermes。诊断只读取安装位置和版本，不会替你删除旧文件。

发现冲突后，先确认自己日常使用的终端实际命中了哪条路径，再决定卸载哪一份。不要只按路径新旧猜测，也不要直接删除一个不认识的系统目录。

## 怎样理解结果

| 结果 | 意思 | 下一步 |
|---|---|---|
| 成功 | 命令完成，重新探测到的版本符合预期 | 在日常终端再跑一次 `--version` |
| 部分成功 | 批量操作里有些工具完成，有些没有 | 逐项查看失败工具的最后一行错误 |
| 硬失败 | 安装或升级命令本身报错 | 检查网络、权限和包管理器输出 |
| 版本未变化 | 命令返回成功，但仍命中旧版本 | 查看多安装位置与 PATH 顺序 |
| 已安装但无法运行 | 文件可能存在，但版本命令启动失败 | 检查运行时版本、shell 与 PATH |

升级结束后，FyAgent 还会为该工具补做一次冲突诊断。没有冲突时会清除旧提示；仍有多份安装时会保留路径列表。

## 推荐的排查顺序

1. 在 FyAgent 中运行该工具的诊断。
2. 在你真正写代码的终端执行该工具的 `--version` 和路径查询命令。
3. 对比 FyAgent 列出的安装位置，确认当前命中项。
4. 通过对应的包管理器卸载多余版本，再重新打开终端。
5. 回到 FyAgent 刷新版本，最后做一次实际调用。

如果问题出在 WSL，请同时核对发行版、shell 和启动参数；Windows 与 WSL 是两个独立环境，某一边安装成功不代表另一边也能直接使用。
