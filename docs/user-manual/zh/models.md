# 模型管理

打开「模型管理」，先在「选择应用」中选定目标，或使用顶部「一键配置主流大模型」与「全端体检与克隆」一次性管理多个客户端。`QoderWork CN` 与 `TRAE Work CN` 仅支持官方模型，第三方模型请在其应用内添加。

## 单端填写与保存

1. 填写配置名称（如有）、服务地址、API Key 和模型 ID。服务地址使用 HTTP(S)，密钥只填写在 API Key 字段。
2. 点击「拉取模型」选择服务返回的模型，或手动填写模型 ID。WorkBuddy、OpenCode 与 Oh My Pi（`omp`）可配置多个模型；先检查待保存列表。
3. 使用已存模型旁的「测速」按钮（或底部「测试连通」）验证可用性。测试会发送极小请求，可能产生极少量用量，即使返回 404 也不会删除或篡改你已保存的模型。
4. 点击「保存并设为当前配置」或「保存并应用」，核对即将改动的配置文件与备份说明后再确认。
5. 检查当前配置是否更新，并按提示在目标软件刷新、重新打开或新建会话（Codex 运行中时顶部会提示一键重启命令行服务或退出重开桌面端）。

Claude Code 的服务地址通常应去掉末尾 `/v1`，以免追加成重复路径；按服务商文档确认。需要本地免鉴权服务时，使用页面提供的「不使用 API Key」。Codex 的 WebSocket 传输、内置生图扩展按服务兼容性选择。

## 一键批量配置、跨端克隆、密钥轮换与我的模板

- **一键配置主流大模型**：选定内置服务商（如 DeepSeek、Kimi、智谱 GLM、阿里云百炼、火山方舟、MiniMax、硅基流动、OpenRouter）或已保存的「我的自定义模板」，粘贴一次 API Key 并勾选目标软件，先预览涉及的文件路径再确认写入。
- **全端模型健康体检**：一次查看 6 款客户端的当前模型、域名与凭证来源，并发测速，并支持从任意已配好客户端「克隆到其他端」、按同域名分组「原地轮换 Key」，或将常用中转站「存为模板」（模板仅存地址与模型，绝不保存 API Key）。
- **失败隔离与回滚**：批量写入、克隆与轮换按目标逐端执行并在写入前保留备份；某一端失败时仅回滚该端原文件并明确提示失败软件，支持一键单独重试失败项。

## 会改动哪些文件与字段，哪些绝不动

| 目标软件         | 会改动的文件路径                                     | 仅更新的字段                                                               | 绝不改动的内容                                                          |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| WorkBuddy        | `~/.workbuddy/models.json`                           | 所选模型条目的服务地址、API Key 与模型 ID                                  | 其他自定义模型、聊天历史、MCP、Skills、官方订阅登录                     |
| Codex            | `~/.codex/config.toml`、`~/.codex/auth.json`         | 当前自定义供应商的地址、协议、模型 ID 与 `OPENAI_API_KEY`                  | 历史会话、提示词（`AGENTS.md`）、MCP 列表、Skills、未修改的其他配置段落 |
| Claude Code      | `~/.claude/settings.json`、`~/.claude.json`          | `env` 内的 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_MODEL` | 历史会话、`CLAUDE.md`、MCP 配置、Skills、权限与其他用户手改设置         |
| OpenCode         | `~/.config/opencode/opencode.json`                   | 目标自定义供应商的 `baseURL`、`apiKey` 与模型列表                          | 其他供应商条目、界面偏好、MCP 与用户自定义字段                          |
| Oh My Pi (`omp`) | `~/.omp/agent/models.yml`、`~/.omp/agent/config.yml` | 指定供应商的地址、协议、密钥与默认模型选择器                               | YAML 注释、其他供应商与未知字段、私有 `agent.db`（绝不触碰）            |
| Grok Build       | `~/.grok/config.toml`                                | 指定模型的地址、名称、协议与密钥                                           | 历史会话、提示词、MCP、Skills 与其他无关字段                            |

**升级与退回旧版保护**：FyAgent 在升级本机数据库结构前会自动创建完整备份并校验；若你从较新版本退回旧版 FyAgent，启动时会明确提示「数据库版本过新，请升级 FyAgent」，绝不会静默破坏或清空已有配置。

## 使用账号订阅

在「使用账号订阅（实验性）」选择已保存的 ChatGPT 或 Grok 账号，查看模型选项或填写支持的模型 ID。Grok 示例选项的实际可用性以服务响应为准。

Codex 点击「保存 Codex 订阅配置」后，继续到「账号与认证」预览并确认来源切换。其他目标按界面「应用到」按钮确认文件更改。使用订阅时保持 FyAgent 在后台运行；完全退出会停止本机转发。调用是否可用以及额度使用以服务返回为准。

账号准备见 [账号与认证](accounts.md)，失败排查见 [问题处理](troubleshooting.md)。
