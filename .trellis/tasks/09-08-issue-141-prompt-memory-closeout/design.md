# 最小修复与恢复设计

## 修改所有者

1. src-tauri/src/services/prompt.rs：upsert 的判断应同时考虑同一条记录保存前的 enabled 状态和请求的新状态。新建/既有 disabled 条目保存是库操作；只有实际 enabled→disabled 转换才进入原有无其他 enabled 时清空 live 的分支。enabled 保存沿用原子文件写入；导入复用同一 upsert，不新增第二套导入写入逻辑。独立审阅发现秒级 imported ID 可能碰撞；显式导入复用现有 UUID 生成独立记录，旧 ID 不迁移，防止覆盖已启用条目后再次误清空。
2. src-tauri/src/commands/workspace.rs：列表、搜索和直接 CRUD 共用现有日记文件准入函数。以现有项目日期语义核对 ASCII 格式与真实日历有效性，复用 chrono 等已有依赖；先过滤再读元数据/内容。保留正常排序、预览和读写路径。
3. 就近已有测试模块承载回归；必要时只扩充现有测试文件，不创建并行 API 或服务。
4. 维护当前 Prompts/Memory 合同与开发说明的对应段落，不复制完整历史审计。

## 数据与兼容

无 schema/协议/依赖变更。Prompt 读取旧状态以实际持久化主键 prompt.id 为准，避免信任未使用的辅助 id 参数。保留原有显式停用与启用操作的语义；不要顺手重写事务系统。日期准入应与 renderer 一致，避免列表输出被端口整批拒绝。

创建分支前已 fetch origin，并核对 GitHub main 精确 SHA一致。当前开放 PR #180 为盘点、#172 为登录，没有这两项修复。原共享工作树中的 V3.1/账号文档等修改不带入。对本地历史候选仅做相关范围核对，以确认是否已有可复用实现；研究结果归 research/implementation-research.md。

## 恢复与隔离

- Git：使用独立修复工作树，分支 codex/issue-141-prompt-memory-closeout。用户交接树保留。以独立修复提交为回退单元；需要回退时 revert 对应提交，不 reset 共享目录。
- 运行：原 /Applications/FyAgent.app 保持。测试构建通过 mise run build:debug 从本分支产出，以独立 FYAGENT_TEST_HOME 启动；启动前检查全局路径覆盖不会将数据库指向真实资料，启动后核对进程与打开数据库。
- 资料：测试输入全为无敏感哨兵值。先保存基线摘要，验证后读取原文件/数据库；只恢复本轮测试 fixture，不自动覆盖用户历史内容。正常用户文件仅做摘要比较。
- 出错：停止相关测试实例，保留失败产物和恢复副本；修复后重建再验。测试结束退出独立实例，恢复正常应用。
- 已丢失内容：本任务防止未来误清空；不猜测或批量恢复旧数据。
