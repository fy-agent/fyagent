# 视觉与组件评审

## 基线

实际浏览器夹具截图（非原生截图）显示账号页默认 h1 为 32px，其他页面多数为20/22px；初始登录弹窗900px宽、标题18px/700、按钮13px/620、头区84px、尾区63px。标题/正文/操作层级不统一。配置、账号之间重复入口在下一个子任务处理。

## 改进

角色化字号与字重、侧栏胶囊圆角、较柔和的选中材质；弹窗标题16px/600、按钮13px/500，账号选择720px。头部/正文共用一个滚动区，footer固定可见。ConfirmDialog去掉空body与重复提示。输入占位文案明确指定可见色，不依赖浏览器灰色默认值。

## 回归发现

1. React autoFocus 先于 Radix 开启事件，会让焦点记录失效。改为初始焦点 ref，由 Radix 事件顺序捕获触发者后再聚焦取消；关闭弹窗仍回到原控件。测试保留。
2. 单独覆盖 Description ID 会导致 Radix 自检告警。保留框架配对ID，只在无描述时明确省略 aria-describedby。
3. 初始截图可能截到 spring 中间态。截图前增加选中host与overlay坐标收敛断言，不把动画中间帧当作布局缺陷。
4. 全量单元与浏览器同时跑造成一项已有综合测试超过5秒；改为顺序复跑，未放宽时限或断言。

## 验证

V2 typecheck/lint通过，73文件515单元测试通过；164项原有浏览器回归通过，新4项多视口视觉/几何检查通过；contracts:prearchive通过。新增截图收敛断言初次未计入侧栏明确的1px inset，核对真实测量实现后按top+1/height-2校验，未改变生产几何或放宽阈值。实际审阅过原始1232x700弹窗，以及修改后的900x600弹窗、1232x700账号页面、最终1232x700弹窗。原生字体、系统窗口和全部对比度组合不在该浏览器证据的证明范围内。
