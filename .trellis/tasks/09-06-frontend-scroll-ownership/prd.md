# 长内容滚动所有权与页面覆盖

## Goal

落实父任务 R1/R4：修复 Skills 无法滚动，并验证同类页签/分栏/弹窗长内容实际可达，避免布局检查通过但用户只能看到前几项。

## Evidence

父 research/current-audit.md A/D：两个生产浏览器中40条Skill使页签高约3069px，页面可用高586px，物理滚轮后列表偏移仍为0；仅约束中间页签的浏览器探针恢复滚动。根因涉及共享FeatureTabPanel和直系子元素CSS合同，不是缺少一个滚轮库。

## Acceptance

- [x] Skills已安装列表/详情/分配、发现结果及末尾动作可用滚轮与键盘到达；空、加载、失败和长内容状态均有效。
- [x] 七个主页面及有独立布局的页签记录滚动owner和最终动作可达证据；不能只检查overflow属性、DOM存在或无横向溢出。
- [x] 四桌面尺寸、窄容器和缩放等价宽度，保活回访/主题切换/模态关闭后不锁住滚动，不丢草稿和选中。
- [x] 合成数据与物理wheel/键盘测试失败于原实现，修复后通过；禁止为验收用scrollTop赋值或自动scrollIntoView偷偷移动不可达内容。
- [x] 复用现有原生滚动/分栏组件；不增加滚动事件代理或自制惯性算法，不修改整体导航布局。
- [x] 更新SPEC、完整预归档检查、工作提交和归档；原生最低系统/GPU未测不得冒充通过。

## Boundary

首个实施子任务；没有产品能力扩展。共享角色收敛只涵盖可证实的滚动边界，不顺带替换应用布局框架。
