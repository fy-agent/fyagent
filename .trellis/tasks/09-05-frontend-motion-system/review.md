# 动效与交互复核

## 实际实现

Motion 继续作为唯一动画/弹簧/手势引擎，Radix 继续拥有模态、键盘、焦点和滚动锁。
按钮、对话框分别迁到具名 owner，调用方全部迁移；没有把旧导出留成第二套实现。
`useDialogState` 按职责从来源几何模块分离，条件编辑器重开时用新 session key；
`ToastViewport` 只接管通知呈现，定时和业务状态仍属于原 FeatureProvider。

- 选择弹簧使用 visualDuration 0.26 / bounce 0.07；按压目标 0.975，视觉硬上限
  1.004，布局占位不变。按钮、导航文字、切换/勾选、分组/列表等复用同一手势。
- 进入/退出分别使用420ms/320ms令牌和共同减速曲线；正文只做有限位移/淡变，
  不随材质压扁。工具提示、popover、内容切换、折叠、进度与toast使用各自角色。
- 显式ref记录真实触发控件。异步打开保留原来源；关闭重新测量。来源已删除、
  裁剪、滚走或不可见时采用中性返回，不用全局最近点击猜来源。
- 退出时立即移除表单与操作DOM，仅保留不可重复提交的材质；隐藏页面立即移除
  portal。取消自动激活页签、新旧modal焦点竞争、pending确认语义均保留。
- 受保护的侧栏导航也传递实际来源：现有PrimaryBlocker只消费一次匹配目标的
  来源意图。路由规则不变，程序化/历史跳转无匹配来源则使用中性效果。
- 系统减少动态效果实时生效，不轮询、不假延迟。材质在静止后启用库增强效果，
  运动时仍用同一玻璃底层样式，不复制页面或秘密表单。

## 测试确实暴露并修复的问题

1. Radix Portal晚于父layout effect挂载，原来的初始化会错过真实DOM；现在以
   committed Content节点启动，不再出现没有来源标记/入场效果的“假实现”。
2. 零时长退出先于Motion父级登记退出key时，会留下模态锁；完成跨一个提交微任务
   边界，旧代次回调作废。不是增加固定延迟或放宽测试超时。
3. Radix组合ref会短暂null再挂回同一DOM；将其误计为新挂载导致循环渲染。
   当前区分真实节点替换与ref重组，DOM只通过ref操作，未添加lint豁免。
4. 原Vitest/jsdom和Node AbortSignal不同realm导致真实Motion手势监听失败；按
   官方测试环境的局部适配模式翻译DOM监听signal，保留native Request/fetch，
   多目标取消、window监听及已取消signal都有实际回归，未丢弃signal或屏蔽错误。
5. 新动画使旧250ms假请求与确认退出竞争；测试改为显式可释放IPC门，继续验证
   禁用按钮与重复提交，而非增加请求时长、删除断言。
6. 材质降级测试直接改CDP feature集合，会无意取消减少动态效果并在入场中抽样；
   现在保留明确的media集合，等待真实settled标记和滤镜/不透明状态，再测4.5:1。
   没有降低对比度门槛、把空computed style当作“none”或关闭动效专项测试。

详细源码/官方依据与职责迁移分别见 `research/continuation-review.md`、
`research/ownership-migration.md`。所有复核为本次执行的分层审查，不声称独立审计。
