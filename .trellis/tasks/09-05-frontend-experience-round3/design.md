# 整合设计

三个子任务按视觉基础、职责清理、启动整合顺序推进。共享规则在 tokens/primitives 和 feature controls 落地，页面仅组合；不改变导航顺序、路由地址、扫描/配置结构。API、秘密处理、原生操作确认和回读属于既有 owner。

评审分为源码/规范核对、实际浏览器页面与几何检查、完整 diff 与回归。父任务负责跨子任务验收。子任务独立提交、归档；父任务最后记录合并结果，避免任务完成状态掩盖未验证的原生行为。

首次调查发现：配置页同时渲染完整安装面板；Codex 模型页额外包含已有 Provider 切换工作区；正常 native setup 直接 show；AppShell 又早于路由完成报告 frontend-ready；启动立即预取所有路由。以上逐项验证，不用纯 CSS 隐藏功能或用固定延迟伪造加载完成。
