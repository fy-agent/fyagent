**最小修正：** 允许对已导入的不可变 manifest 做一次显式分享预览和确认，导出该固定身份/摘要对应的原样包内容；沿用严格 schema、已知秘密模式拒绝、可信文件选择、不可覆盖写入及 native 回读。不加入项目输入、账号映射、运行结果或目录，不把第三方来源标成内置/已脱敏/已验证。对非内置内容用准确提示让使用者审阅内容再确认，而非新增审核系统。`local_fixture` 的机器校验继续只允许受审内置样本，不因允许原样导出扩大执行权限。

**最小验收：** 将现有 `custom-kit` 导入用例延伸为“预览取消零写入 → 明确确认导出 → 空库导入后 kit ID/version/digest 一致”，同时证明第三方包仍不能获得 builtin 或 local_fixture 身份，含秘密模式和追加项目数据字段仍拒绝。前端同步去掉 exportable 与 builtin 的硬绑定，分享文案按真实内容来源显示，避免继续写“仅包含内置模板”。无需通用权限框架。

## 已核对且无阻断的行为

- **严格纯文本边界。** `schema.rs:179-257` 在 typed decode 前递归拒绝重复/原型敏感 key，并限制体积、深度和字符串大小；`:300-414` 的 deny_unknown_fields、闭合枚举、资源摘要及引用检查阻止任意 path/env/command/启用字段。权限只有 read；资源只接受 Markdown/JSON，`KitContent` 以 React `<pre>` 惰性文本显示，无 HTML 执行或远程图片加载。秘密模式扫描明确只是拒绝辅助，不能保证任意第三方文字不含商业机密。
- **导入不激活。** `commands/delivery_kits.rs:27-60` 通过 native picker 选文件，apply 只接受 previewId/digest；库 service 不调用凭据服务、网络、工具分配或脚本执行。预览只存在内存，UI 只在确认后 apply，并经目录回读后显示“已加入库、尚未绑定”。
- **不可变与冲突。** `mod.rs:203-240、262-315` 区分 preview 身份/TTL、同版本异内容冲突和相同内容幂等；使用临时私有文件、sync、persist_noclobber 及实际回读，不直接覆盖现有版本。已有并发原生测试覆盖多个 library 实例同时发布一个版本。文件库没有破坏性删除 API。
- **真实闭合计算。** `validator.rs:66-148` 从输入独立累计整数金额、检查重复/期间/币种/零分母，再计算指标；`:187-211` 才与 expected 对比。原生测试 `tests.rs:190-220` 断言 180000 / 150000、增长 20%、目标 90%，并证明篡改 expected 不会替换实际计算结果。负例的“符合样例预期”不会把其业务错误改成成功。
- **边界准确。** 只有内置经营周报允许机器校验；知识客服和经营查询有实际正反样例与人工核对说明，UI 未声称已经连接 RAG、数据库或客户已验收。导入包自称 synthetic 不会自动获得机器来源类别。
- **取消、错误和迟到结果。** `ProjectDeliveryKitsPanel.tsx:39-90、103-153` 按项目/修订重建 session；隐藏时卸载，迟到 preview 被取消，迟到业务结果不写入新项目页面。操作有同步锁，错误通过闭合文案映射；保存对话框取消返回 false，不显示导出成功。native export 在文件选择前后重查 preview/TTL，防止过期内容落盘。原生 readback/冲突错误不升级成功。
