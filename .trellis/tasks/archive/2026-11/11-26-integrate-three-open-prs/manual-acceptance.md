# 人工接手：原生体验与阻塞清单

这些是验收步骤，不是实测结论；实际记录见 [execution-result.md](execution-result.md)。区分原生服务、桌面操作和远端平台，未观察到的结果不标通过。

## H1 — Windows x64 启动

1. H1 可使用日常 Windows 普通账户，不要求 VM。先核验两个 EXE 的 SHA-256，并确认没有运行中的 FyAgent 实例；不覆盖安装、不提权。仅检查启动、导航和退出，不执行同步、恢复、安装或配置写入操作。
2. 从该账号 PowerShell 执行 `Start-Process -FilePath '<验收产物完整路径>' -PassThru`。记录启动时间、进程名、主窗出现时间；如果窗口不出现，记录是否退出、退出码或 Windows 事件，不把仍有进程当作启动成功。打开顶部迁移入口及模型、MCP、会话页，检查能进入、返回且没有白屏；退出程序后确认不再残留本次进程。
3. **通过**：同一哈希版本打开各入口并正常退出。日常环境只做此冒烟；真实配置写入和外部服务仍按各专项前提执行。

## H2 — WSL 真实同步

1. 单独测试 VM/发行版和普通 Linux 用户。以 `wsl.exe --list --verbose` 确认发行版，用 `wsl.exe -d <测试发行版> --exec /bin/sh -lc 'id; printf "%s\n" "$HOME"; command -v base64; command -v sha256sum'` 核验落盘身份与依赖。现有 `Ubuntu-24.04` 能执行 shell，但尚未证明适合作为产品落盘目标。
2. 在隔离应用中创建只含假数据的可迁移配置。顶部“迁移”→“同步到 WSL”，选择测试发行版；使用 `~/fyagent-review/<run-id>` 作自定义目标根，选择一项已准备好且可预览的内容。记下路径与动作；按预览的输出确认全部目标均处于测试根。预览前后读取测试目录文件清单和哈希，应该无产品配置写入。`reachable=false`、动作未知或预览为空时不点应用。
3. 先同步到空测试根，使用同一 WSL 用户回读生成文件；例如对预览给出的单个相对路径执行 `stat -c '%a %n' -- "$HOME/fyagent-review/<run-id>/<相对路径>"` 和 `sha256sum -- <同一路径>`。将一个普通测试文件的内容替换为已知旧值，再走预览和应用，检查该文件由“创建”变为“更新”，备份 `~/.fyagent-wsl-backups/<应用返回的批次>` 中是旧内容。备份目录也必须在专用 Linux home；只记录路径、权限和哈希，不输出密钥内容。
4. **通过**：准确目标、预览不写、应用回读匹配、覆盖有旧内容备份，若选择含假密钥的文件其 mode 为 `600`。缺 WSL、路径/用户不符、预览与回读不同都记录具体阶段和错误；不改用现有用户 home 补测。

## H3 — SSH 档案、实际探测与推送

1. 由操作者提供绑定环回的测试 SSH 服务，或显式获准的隔离测试机；服务端普通测试账号的 home 专用，采用一次性专用身份文件、独立 `known_hosts` 数据。通过管理端获取并核对宿主公钥指纹，在测试账户中预置正确主机记录，不依赖产品首次连接的 `accept-new`。不使用生产主机、不关闭主机校验、不把私钥内容交给分类器或日志。
2. 在测试账户建立专用 Host 别名。先执行 `ssh.exe -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=10 <测试别名> 'id; printf "%s\n" "$HOME"; command -v sh; command -v base64'`。连不通先记录错误类别（无服务、主机校验、认证、远端依赖），不要运行产品推送。
3. “迁移”→“推送到 SSH 远端”，选测试别名与 `~/fyagent-review/<run-id>`，保存常用主机；退出再打开，选中档案确认目标/用户/端口/映射回填。运行“测试连接”，预览确认目标和路径与第 2 步一致；再推送、用 SSH 回读校验哈希，覆盖一次验证 `~/.fyagent-remote-backups/<批次>`。删除档案、重开确认不再显示。档案只保存身份文件引用，不把 Key 内容、密码写进字段或报告。
4. **通过**：档案创建/重启回填/删除成立，推送和备份在正确测试目标回读一致。没有 `sshd` 或获准目标时，由测试环境管理员接手第 1 步；T2 通过不能把 H3 标为通过。

## H4 — Keenable 目录与真实连通分开验收

在测试账号打开 MCP 目录搜索“Keenable 搜索”。核对官方远程 HTTP、Key 可选及查询词/抓取 URL 会发给远程服务的提示。只先生成无 Key 的测试配置，确认没有 Authorization。目录检查不要求联网；**只有操作者批准出站且测试客户端支持 Streamable HTTP**，才在隔离客户端用不含私密信息的固定查询验证连接、列工具与响应，记录服务错误类别（DNS、TLS、限流、协议等），不记完整头或令牌。接通失败不推翻已通过的目录验收，也不算远程可用。

## H5 — 模型写入边界

在专用 Windows 用户中为 OpenCode、omp 建立合法合成配置，包含无关 provider 和自定义字段；复制到测试证据目录作基线。分别走模型页批量写入、体检的“克隆”和“轮换”预览，观察所选软件和保护范围，取消一次应保持文件哈希不变。实际写入仅选已准备的测试目标，假 Key 不用于联网；按结构比较确认批量/克隆只改选定模型项、轮换只更新选定 Key。备份应含旧值，无关 provider、MCP、Skills、会话内容保持原样。记录变更字段名和哈希，不贴认证字段值。未准备相应客户端/目标数据时按具体子场景标 `BLOCKED`。

## H6 — 会话恢复门控与可访问错误

1. 在隔离 Windows 用户准备合成会话包和受当前写规则支持的 Codex 测试版本。原生首次启动前，“会话”→“导入会话包”→选文件并解析：检查恢复不可用且提示先启动；只读检查没有创建 `installation_id`。由 Codex 自己首次启动生成身份，不手写或复制真实身份文件；重新打开导入后观察重新探测，并只对合成数据确认恢复和只读回查。用合法但无法恢复的合成包或独立错误 fixture 检查中文错误可由键盘定位、滚动到可见区且无假成功。
2. 在同样隔离条件下验证 Gemini：仅当可写规则确认支持时，提取不可用不应阻止恢复；未安装或写规则不支持仍禁用。错误不得诱导绕过版本或身份门。标题验证使用含结构化上下文和真实提示文本的合成记录，标题取真实提示而非附件内容。
3. **通过**：记录初始化前/后恢复状态、明确的错误行为与恢复结果。不具备兼容客户端时，由对应客户端验收人接手；T5 fixture 不能代替这一环境。

## H7 — macOS Claude npm 归属

Windows 无法提供真实 Homebrew 所有权证据。由 macOS 验收人使用隔离机器或账户分别准备同 prefix 的官方 Claude npm 安装与实际 Homebrew 管理的样本；分别通过 `command -v claude`、`npm prefix -g` 和正常路径解析确认观察输入，再用应用的 Claude 安装/检测界面只读复核所有权。不用生产机器重装、迁移或提权，不把 Windows 字符串 fixture 当 macOS 实测。同 prefix 官方包识别为 npm；真实 Cellar/Caskroom 和跨 prefix 不接管。若用仓库内 macOS loopback SSH 测试补证 SSH，先确认 `/usr/sbin/sshd` 和真实测试执行；它会在缺服务时提前返回，不能从绿色计数推断 Windows SSH 通过。

## 交接记录格式

每个阻塞单独记录：`ID / 分类 A、B 或 C / PASS、FAIL、BLOCKED、NOT_RUN / 源码 HEAD 与 exe SHA-256 / 预期与实际 / 最短复现命令或界面步骤 / 脱敏证据 / 谁提供什么才能继续 / 解除标准`。A＝源码、权限或合并阻塞；B＝本地依赖、SDK、构建环境；C＝需要人工提供隔离运行环境、真实服务或另一平台。同一场景只有实际观察到输出或回读，才标 `PASS`。不能提供测试前提不是验证失败，但也不算通过。
