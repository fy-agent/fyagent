# 精简并校准全部 Trellis spec

## 背景

`.trellis/spec/**` 已积累 41 份 Markdown、14,883 行内容。核心安全、发布、
跨平台合同需要保留足够深度，但部分文档同时承担了长期规则、某次迁移记录、
当前实现快照和重复说明，导致：

- 当前规则需要依赖顶部 `override` 才能覆盖正文中的旧规则；
- 版本号、提交 SHA、一次性迁移日期等易变事实被复制到长期 spec；
- 索引、思考指南、通用规范和功能合同重复描述同一行为；
- 读者难以判断哪一份文档是权威合同，哪一份只是历史证据。

## 目标

1. 逐份审查现有 41 份 spec，并留下可追溯的处置清单。
2. 把当前有效规则直接合入正文，移除日期化 override 和已失效的被覆盖条款。
3. 将索引、指南和通用规范压缩为稳定的导航、原则和边界；具体 DTO、错误矩阵、
   测试与安全闭包继续由对应功能合同拥有。
4. 将历史 SHA、一次性迁移证据和易变工具版本交给 Git、provenance 文档、
   权威配置文件及可执行测试，不在多个 spec 中复制。
5. 保留安全、权限、TOCTOU、secret、签名、回滚、原生平台和发布事务的完整合同。

## 非目标

- 不改变产品行为、IPC、数据库、CI、Release、安装器或运行时实现。
- 不删除归档任务、CHANGELOG、Git 历史或 `docs/upstream/**` provenance 证据。
- 不以行数为唯一目标，不机械缩短高风险合同。
- 不新增另一套 spec 分类或文档生成框架。

## 验收标准

- `research/spec-inventory.md` 覆盖全部 41 份 spec，并说明保留、更新或精简理由。
- backend、frontend、guides 三个索引完整链接本目录所有文档，且无失效相对链接。
- 现行行为不再依赖日期化 `override` / `integration note`；被覆盖的旧正文已删除或改写。
- 通用规范不再复制功能合同中的大段页面、DTO、版本和历史证据。
- 易变版本以仓库权威文件为来源；历史上游导入事实链接到 provenance ledger。
- 所有修改通过 Markdown/链接/索引/重复与敏感标记静态审计、Trellis 校验、
  `git diff --check` 和仓库适用的文档/合同检查。
- 至少完成三轮评审：结构完整性、语义/权威边界、最终 diff 与验收门禁。

## 风险控制

- 高风险合同默认保留，只有确认存在重复、失效或历史快照时才修改。
- 任何删除都必须能指向新的唯一权威来源。
- 文档变更不宣称真实原生平台、签名、安装、供应商集成或发布证据。
