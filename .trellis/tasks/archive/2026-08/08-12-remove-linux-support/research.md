# Research: Windows and macOS only

## Purpose and evidence boundary

This inventory identifies every current first-party surface that implements,
builds, tests, publishes, documents, or implicitly admits the platform support
being retired by this task. It is planning evidence, not implementation proof.

All facts were collected from the current tracked checkout on branch
`dev/laiyongjie`. Existing `.trellis/tasks/archive/**` files are intentionally
excluded by user decision. The active task is also excluded from negative
searches because it must name and explain the work; after completion it will be
inside the same archived-task exclusion.

Approved generated-metadata exception:

- `pnpm-lock.yaml`: platform-specific optional packages generated for tools
  such as esbuild, Rollup, the Tauri CLI, and lightningcss.
- `src-tauri/Cargo.lock`: transitive target metadata generated by Cargo.

The exception is limited to reproducible third-party transitive metadata. It
does not cover `package.json`, `src-tauri/Cargo.toml`, `mise.lock`, source,
scripts, workflows, tests, documentation, or current specs. Frozen/locked
installation must continue to pass.

## Target invariant

The repository's current supported desktop set becomes exactly:

```text
windows
macos
```

WSL is explicitly retired even though it is invoked from Windows. Unknown or
unsupported platform handling may remain only as a fail-closed outcome; it may
not detect, expose, configure, install, update, launch, build, test, package,
or document the retired platform.

The implementation audit must test both direct and implicit admission:

- explicit platform names, target triples, runners, package formats, desktop
  metadata, paths, and commands;
- Rust `cfg(unix)`, `cfg(not(windows))`, and other negative platform filters
  that would continue compiling an unintended target;
- TypeScript/JavaScript `!isWindows`, `process.platform !== "win32"`, or generic
  POSIX fallbacks that should be explicit macOS branches;
- data contracts, persisted settings, IPC payloads, fixtures, generated asset
  counts, and exact workflow dependency sets whose names do not contain a
  platform token.

## Baseline inventory

An initial broad tracked-file scan found platform-related semantics in 242
files before the active task was excluded. The largest groups were current and
historical documentation, Trellis archives/specs, native source, frontend
source, scripts, workflows, and executable contract tests.

The audit also found structural patterns that a token scan would miss:

- roughly 198 Rust lines across 30 files using `not(windows)` or equivalent;
- roughly 45 Rust lines across 17 files using `cfg(unix)`;
- several JavaScript/TypeScript non-Windows fallbacks;
- the persisted `useAppWindowControls` field, which has no platform name but
  exists only for the retired native window path;
- WSL IPC arguments and DTO fields propagated across renderer and Rust.

Two SVG assets contain incidental byte-sequence matches inside embedded base64
data. They are not platform assets or semantic references and must not be
deleted or re-encoded merely to satisfy an unstructured substring scan.

## Renderer and shared frontend contracts

### Window chrome and platform detection

The legacy renderer implements a target-specific custom chrome chain:

```text
Rust Settings.useAppWindowControls
  -> TypeScript Settings
  -> useSettingsForm
  -> WindowSettings toggle
  -> App setDecorations()
  -> custom caption controls and drag rules
```

Affected owners include:

- `src/lib/platform.ts:21-48`: platform detection and Wayland/GTK drag-region
  guards;
- `src/App.tsx:134,241,269-273,554-597,976-1012,1331-1380,1406-1414,
  1518-1521`: dynamic decorations, caption actions, geometry, and drag regions;
- `src/components/common/FullScreenPanel.tsx:28,97-126`: duplicated geometry
  and drag behavior;
- `src/components/settings/WindowSettings.tsx:80-90`: platform-only toggle;
- `src/types.ts:355-356` and `src/hooks/useSettingsForm.ts:110-181`: persisted
  field and form defaults;
- four locale files: caption-action, failure, and setting strings.

After removal, Windows keeps a zero-height legacy drag bar and macOS keeps its
system-titlebar geometry. Both must keep system decorations. Old persisted
unknown fields should be ignored safely without retaining runtime behavior.

V2 platform types/detection also require contraction:

- `src/v2/shared/platform/types.ts:1-6`;
- `src/v2/shared/platform/runtime.ts:19-43`;
- `tests/v2/platform/runtime.test.ts:20-35`.

`unknown` remains a useful fail-closed value; it is not a supported platform.

### WSL renderer and IPC flow

`src/components/settings/AboutSection.tsx` contains the renderer half of the
WSL product contract:

- environment union and `wsl_distro` (`48-58`);
- WSL shell preference/options and environment badges (`77-110`);
- per-tool WSL state, probes, handlers, lifecycle calls, distro display, and
  selectors (`242-244`, `282-386`, `419-421`, `510-523`, `646-658`,
  `910-916`, `970-1009`).

`src/lib/api/settings.ts:248-280` carries the same behavior over Tauri IPC via
`getToolVersions` and `runToolLifecycleAction`. Renderer signatures, invoke
payloads, Rust command arguments, DTO fields, tests, and mocks must change in
one coherent batch so an intermediate layer cannot silently retain support.

Four locale files contain WSL/platform badges, shell controls, configuration
directory guidance, and `/home/<user>` examples. The directory examples and
fixtures should become Windows/macOS-specific or platform-neutral without
removing POSIX behavior still required by macOS.

### Terminal and generic POSIX fallbacks

`src/components/settings/TerminalSettings.tsx` has platform-specific terminal
options/defaults. It must become a positive Windows/macOS allowlist. Shared
terminals used by macOS must not be removed simply because they also exist on
another platform. Old persisted values should normalize through a generic
unsupported value without retaining deleted names.

`AboutSection` one-click commands and `src/config/mcpPresets.ts` use a generic
non-Windows/POSIX fallback. The shell mechanisms remain necessary on macOS,
but selection must become explicit Windows/macOS logic so an unknown platform
does not inherit a third supported path.

### Acceptance fixtures

The desktop acceptance platform source and visual manifest currently enumerate
three platforms:

- `tests/desktop-acceptance/fixtures.ts`;
- `tests/desktop-acceptance/desktopAcceptanceContract.test.ts`;
- `tests/e2e/visual-baselines/manifest.json`.

They must contract to Windows/macOS while preserving their single-source and
exact-set assertions. Generic unsupported-platform behavior in the Codex
Desktop installer remains fail-closed; only platform-specific test wording and
fixtures should be generalized.

## CI control plane

### Direct target job

`.github/workflows/ci.yml:364-443` defines `backend-linux`, installs native
GTK/WebKit dependencies, and runs Rust formatting/check/Clippy/tests. It is a
dependency of the stable `.github/workflows/ci.yml:720-766` `CI / Required`
aggregate.

Deleting the job requires a responsibility transfer, not a weaker gate:

- move the currently unique `cargo fmt --all --check` step to a remaining
  backend job and include it in that job's exact step-outcome evaluator;
- remove the job from workflow `needs`;
- update `scripts/ci/required-gate.mjs` exact job IDs, display names, and domain
  mapping;
- preserve the `CI / Required` public name, permissions, current-attempt Jobs
  API verification, triggers, and change-classifier behavior;
- retain backend coverage on both Windows and macOS.

### Platform-neutral jobs on Ubuntu

The current workflows also run repository classification, frontend/contracts,
desktop acceptance, aggregate, labeler, and release control-plane jobs on
Ubuntu even though they do not produce a platform package. The user requested
that platform-related content disappear from CI, so these runners are in scope
and will migrate to a remaining supported runner rather than remain as an
infrastructure exception.

Prefer macOS for Bash-heavy control-plane jobs where it preserves the current
execution model. Audit and replace GNU-specific commands (`stat -c`,
`sha256sum`, and similar) with portable project scripts or explicit macOS
equivalents. Labeler can move without a shell rewrite. Tests must assert the
new exact runner set and must not merely stop checking runner identity.

## Audit design

Final audit has three layers:

1. Tracked filenames for platform names, package formats, target triples,
   desktop metadata, WSL identifiers, distro names, and tooling paths.
2. Tracked text using bounded semantic patterns with a closed exclusion list:
   `.trellis/tasks/archive/**`; this exact active task path only before
   archival; generated third-party metadata in `pnpm-lock.yaml` and
   `src-tauri/Cargo.lock`; and opaque encoded SVG payloads. No other current
   historical document receives an exclusion.
3. Structural inspection/tests for negative platform predicates, supported-set
   constants, workflow needs, artifact counts, persistent fields, IPC payloads,
   and generic non-Windows fallbacks.

Every residual must have a file/line, classification, and reason. Incidental
base64 substrings are false positives; first-party generic fallbacks are not.
