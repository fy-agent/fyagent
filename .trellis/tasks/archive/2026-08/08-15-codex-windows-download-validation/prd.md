# 统一 FyAgent 软件一键安装免内容校验策略

## Goal

建立一条跨平台、跨产品的 FyAgent 软件一键安装规则：FyAgent 负责选择安装来源、下载或委托包管理器，并调用平台安装机制，但不再自行判定下载产物的内容是否符合某个需要随上游维护的身份、版本、签名、哈希或包结构规则。上游改变包清单或发布字段时，不应再因为 FyAgent 内置校验规则而阻断安装。

这条规则既要解决当前 Windows Codex Desktop 因 `PACKAGE_IDENTITY_MISMATCH` 无法安装的问题，也要约束 macOS Codex Desktop、现有 CLI 工具安装入口，以及后续新增的所有软件一键安装/升级能力。

## Confirmed Facts

- 用户明确要求该策略不局限于 Windows 或 Codex，而要覆盖所有平台、当前及未来通过 FyAgent 发起的可执行软件一键安装；Skills、插件、MCP 和配置包不属于该策略。
- 当前 Codex Desktop 自建安装链在 Windows 和 macOS 都会下载产物并执行 FyAgent 自有内容校验。Windows 会检查 MSIX 名称、Publisher、版本、架构、最低系统版本、结构及 SHA-256；macOS 会检查 DMG/应用包、Bundle ID、Team ID、签名、Gatekeeper、版本、架构及 SHA-256。
- 当前 Windows 错误 `PACKAGE_IDENTITY_MISMATCH` 可由名称、Publisher、包版本或最低系统版本与 FyAgent 记录的发布信息不一致触发。
- “设置 → 关于 → 工具管理”已经提供 Claude Code、Gemini CLI、Grok Build、OpenCode、OpenClaw 和 Hermes 的安装/升级入口。它们主要委托 npm、工具自身升级命令或官方安装脚本，不由 FyAgent 检查下载内容；执行后会重新探测版本和可运行性。
- Codex CLI 当前只做版本探测，不提供该工具管理入口中的安装/升级操作。
- Windows `PackageManager`、系统包管理器和操作系统自身可能强制执行其原生规则；FyAgent 不能把“自身不校验”表述为“系统不会校验”。

## Requirements

### R1. 全局软件安装策略

- 该策略必须适用于 Windows、macOS 及未来支持的平台。
- 该策略必须适用于当前和未来由 FyAgent 发起的应用、Agent、CLI 工具及 FyAgent 自身更新器（如果未来增加）的一键安装或升级。
- 该策略只适用于交给操作系统、包管理器或官方软件安装脚本处理的可执行软件安装包，不适用于由 FyAgent 直接解压、解析、导入、同步或写入用户目录的 Skills、插件、MCP、配置包及其他扩展内容。
- 新增安装器不得以产品或平台例外重新引入需要跟踪上游包字段的 FyAgent 内容校验。

### R2. FyAgent 不以下载内容判定是否允许安装

- 当前 Codex Desktop Windows/macOS 链路不得再因下载产物的固定 Identity、Publisher、Bundle ID、Team ID、版本、最低系统版本、签名/Gatekeeper 结果、哈希、包内文件布局或其他内容属性而在调用原生安装机制前拒绝安装。
- 远端 metadata 可以继续用于展示版本、选择平台/架构对应的下载入口和组织安装流程，但不得再作为下载内容的比对基准。
- 如操作流程必须读取包元数据以获得安装目标或后续启动标识，该读取只能服务于流程编排，不得把与 FyAgent 内置期望值不一致作为拒绝安装的理由。
- macOS 安装流程仍可为了找到要复制的应用而要求挂载结果中存在一个可操作的应用目录；Windows 仍可读取原生安装所需的包定位信息。这类操作性读取不得扩展为与固定上游身份或包布局比较的准入校验。

### R3. 原生安装机制是最终结果来源

- FyAgent 必须把下载产物交给当前平台或所选包管理器的正常安装入口，并保留其默认行为；本任务不绕过 Windows `PackageManager`、npm、工具官方安装脚本或操作系统不可关闭的安全策略。
- 原生安装机制拒绝产物时，FyAgent 应如实报告安装失败，不得把失败伪装为安装成功，也不得继续执行依赖安装成功的启动步骤。

### R4. 安装后结果探测继续保留

- “不校验下载内容”不等于“不验证用户结果”。安装命令或原生安装机制返回后，FyAgent 仍应重新探测目标是否已安装、版本是否可读取、是否可运行，并据此展示成功、失败或需要用户介入。
- 现有 CLI 工具安装/升级入口的串行执行、冲突提示和安装后版本探测不得因本任务退化。

### R5. 当前 Codex Desktop 迁移

- Windows 和 macOS Codex Desktop 必须同时迁移到新策略，不能只消除当前 Windows 错误分支。
- 需要同步收敛后台状态机、稳定错误码、前端文案、DTO/fixture、平台实现、用户辅助进程协议以及相关测试，删除不再成立的“已由 FyAgent 验证下载包”主张。
- 安装后发现目标不存在、无法启动或原生安装失败时，仍需返回可解释、可重试的结果。

### R6. 未来约束与维护边界

- 在现有安装器责任规范中记录平台无关的全局规则，并让当前实现与测试体现该规则。
- 不为未来尚不存在的安装器创建新的通用框架、下载器抽象或产品占位代码。
- 与一键安装无关的完整性校验不得顺带删除。
- Skills、插件、MCP、配置包及其他扩展内容现有的格式、路径、解压、来源、写入目标和完整性安全校验必须保持不变。

### R7. 用户可见说明

- 用户文档和安装界面不得暗示 FyAgent 已验证下载产物的发布者、签名、哈希或包身份。
- 需要明确说明安装结果仍受来源端、包管理器和操作系统原生行为约束。

### R8. 保留不依赖上游字段的操作安全

- 必须保留 HTTP 状态、重定向策略、超时、取消、磁盘空间、短写/截断、刷新、落盘和清理错误处理。
- 必须保留临时目录、文件权限、ACL、防符号链接/重解析点、防替换、固定下载入口以及跨权限边界的文件对象绑定。
- 下载完成后可以根据实际收到的字节计算本地动态大小和指纹，并在后续交接中用它证明仍是同一个文件；该值不得与厂商 checksum、远端 manifest checksum 或 FyAgent 内置摘要比较。
- 必须保留平台原生安装结果以及安装后的目标存在性、版本和可运行性探测。

## Acceptance Criteria

- [ ] Windows Codex Desktop 下载包即使改变 MSIX Identity、Publisher、版本或最低系统版本，也不会再被 FyAgent 的内容一致性预检以 `PACKAGE_IDENTITY_MISMATCH` 拒绝，而会进入正常原生安装调用。
- [ ] macOS Codex Desktop 下载包不会再因 Bundle ID、Team ID、版本、架构、签名/Gatekeeper 或包内容一致性检查而被 FyAgent 在安装前拒绝。
- [ ] Codex Desktop 下载内容不再与远端 checksum、size、manifest 或 FyAgent 固定身份常量进行准入比对。
- [ ] 下载到安装器的跨进程/跨权限交接使用实际下载结果生成的本地动态大小和指纹防止替换，但没有任何厂商摘要、远端摘要或内置摘要参与准入。
- [ ] 平台原生安装或包管理器拒绝产物时，FyAgent 返回失败；安装后未发现目标或目标不可运行时，不报告成功。
- [ ] 现有六个 CLI 工具的一键安装/升级仍委托现有包管理器或官方脚本，并继续执行安装后版本/可运行性探测。
- [ ] Skills、插件、MCP、配置包及其他扩展内容的现有校验、导入和写入安全边界没有因本任务改变。
- [ ] Windows/macOS 后台、共享 DTO、前端状态与四种语言文案不再暴露已经失去语义的下载内容校验阶段或错误说明。
- [ ] 当前 Codex Desktop 安装、CLI 工具生命周期以及未来安装策略的相关规范和自动化测试通过；无法在本机执行的平台原生安装验证被明确列为剩余风险。

## Out of Scope

- 绕过、关闭或修改 Windows、macOS、npm 或其他包管理器自身强制执行的安全和完整性规则。
- 为尚未存在的未来 Agent/工具实现具体安装器。
- Skills、插件、MCP、配置包及其他扩展内容的下载、解压、解析、导入、同步、完整性校验和写入行为。
- 删除 FyAgent 发布流水线、CI/release 资产、云同步、数据库或其他与用户发起的软件一键安装无关的校验。
- 与本任务无关的安装 UI 重设计、下载源切换或大范围安装架构重构。
