# V2 模型真实连通测试

## Goal

V2 模型页在已经拿到模型列表之后，可以对选定模型发一次真实流式请求，验证鉴权、模型和端点是否真的能用，并把上游错误原文展示给用户。

## Requirements

- WorkBuddy、Claude Code、Codex、Grok Build、OpenCode 的模型配置面板提供「测试连通」。
- 按钮只在当前面板已有可选模型 ID 时出现（拉取成功或手动填入后）。Qoder、TRAE 不提供该按钮。
- 按下后打开选择对话框：按模型 ID 搜索，并按模型分组过滤；用户必须先选一个模型再开始测试。
- 测试发送真实流式模型请求（首个 chunk 即成功），不是 `stream_check_url` 的无鉴权 URL GET。
- 失败时把后端返回的错误信息展示给用户（含 HTTP 状态和截断后的上游响应体），不得用「请检查地址和网络」这类空泛文案替换。
- 成功时展示所用模型和耗时；首 token 过慢标为较慢。
- 连通测试 UI 抽成专用组件，三个面板复用，不各自复制一套搜索/分组/结果展示。
- 不查找已保存 Provider，不写入配置，不触碰故障转移熔断器。
- 错误、日志、DOM 不得回显 API Key。

## Acceptance Criteria

- [ ] 没有可选模型 ID 时，「测试连通」不渲染。
- [ ] Qoder / TRAE 模型页始终没有「测试连通」。
- [ ] 选择对话框含搜索和分组过滤；未选模型不能开始测试。
- [ ] 探测走新 IPC，按产品协议发真实流式请求，并带上草稿 URL、API Key、选定模型 ID。
- [ ] 401/模型不存在等失败把上游错误信息显示在结果里。
- [ ] 三个面板共用同一个连通测试组件。
- [ ] 现有 URL 可达性服务保留，但模型页不再用它充当「测试连通」。
