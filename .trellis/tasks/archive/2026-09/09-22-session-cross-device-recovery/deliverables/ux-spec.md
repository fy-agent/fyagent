## 1. 设计概述与核心契约（定向修正）

### 1.1 核心价值定位：以 Session 替代记忆一级入口
- **一级入口更替**：以「会话（Sessions）」全面替代原「记忆（Memory）」作为侧边栏的一级入口。
- **定位**：会话模块聚焦于多设备间真实对话记录的浏览检索、跨设备轻量导出与目标机原生对应软件的接续。
- **旧记忆能力绝不削弱**：
  - 现有客户端本地的 `MEMORY.md`、`USER.md` 等长期记忆文件完全保留在原位置。
  - **保留原编辑能力**：在侧栏辅助入口保留跳转至原记忆编辑页面的通道，绝不新建只读抽屉削弱原有编辑能力，也不将旧记忆伪造成会话。

### 1.2 严格的 Final-Only 精简契约与不可判定处理
1. **仅保留两项核心文本**：
   - 每轮用户原始提示词（保留用户主动粘贴的文本与代码）。
   - 每轮 AI 最终答复原文（保留正文格式与代码示例）。
2. **彻底剔除与禁止项**：
   - 彻底排除工具调用、参数、工具结果、执行日志、思考过程（Reasoning）、进度播报、附件及工作区文件。
   - 严禁通过夹带隐藏的原生执行日志或全量事件包来实现伪恢复；不做二次模型摘要。
3. **最终答复不可判定时的严格处置**：
   - **禁止绕过精简契约**：当适配器无法可靠判定最后一轮是否为最终答复时，**必须直接阻止该会话导出，或明确标为不可迁移的未就绪状态**。
   - **严禁提供“允许用户确认后勾选携带未判定轮次”的后门**，彻底杜绝中间工具或进度文本渗入迁移包。

### 1.3 恢复边界与验证语义严肃区分
依据 `evidence/codex-probe/findings.md` 的实测结果：
- Codex 0.154.0 中 `thread/inject_items` 虽接口成功且磁盘落盘，但 **历史查询为空，桌面UI展示未验证**；最新本机模拟请求已证明重启后四条历史进入下轮请求，但不是真实模型续聊。因此不得据此断言恢复成功。
- **状态正交解耦原则**：客户端底层恢复能力（`capability`：已验证 / 当前版本尚未验证）与用户操作修饰（`userConfirmed` 用户手动标记、`workspace` 目录重映射）必须严格拆开。用户点击手动确认或完成工作区映射，**绝不可提升软件底层的恢复能力**。
- **恢复写入双重守卫**：在向目标软件写入恢复时，除检查版本能力外，**同样必须拦截任一未判定答复（isIndeterminate）轮次**，严禁将不确定内容写回目标客户端。
- **用户确认 ≠ 客观系统验收**：用户在界面点击“我已手动续聊”仅作为前端标注，不能等同于自动化测试、重启后读回或 Mac/Windows 双向验证。
- **不生成伪命令**：在未取得真实验证的原生会话 ID 前，不生成跨客户端的伪可执行命令，仅提供交互指引与模拟说明。
- **对应软件原生恢复**：七个软件各自走对应原生恢复路线，**严禁向用户推荐跨软件格式转换**。

## 4. 关键交互流程与产品合同修正

### 4.1 导出交互与演示规范（预览纯文本问答）
1. 用户在会话详情点击「预览导出内容（演示）」。
2. **前置契约校验**：
   - 若会话中存在“最终答复不可判定”轮次，**立即弹窗拦截并锁定导出**：“该会话存在无法确认是否为最终答复的轮次。根据迁移契约，禁止导出含有不确定内容的会话。”
   - 绝不提供任何强行携带未判定内容的旁路。
3. **内容生成原则**：
   - 原型仅作交互展示，不生成或下载尚未冻结的生产标准包，以预览窗展示纯文本“用户提示词 + 最终答复”；
   - 若轮次中无 final answer（如未完成轮次），**直接省略该回复项，严禁填入空字段或占位假数据**；
   - 界面明确标注“仅供交互演示预览，非可导入生产包”。

### 4.2 目标机导入与重复冲突防护（禁止覆盖）
1. 目标机打开「导入会话包」，解析精简会话文件。
2. **重复导入检测（禁止覆盖既有原生历史）**：
   - 若检测到相同来源会话已存在：
     - **默认操作**：直接定位并打开已有记录（或跳过导入）；
     - **次级可选操作**：由用户明确点击后，另存为独立新副本并生成新原生 ID；
     - **彻底删除“覆盖既有记录”选项**，杜绝任何覆写损坏已有原生历史的可能。
3. **工作区目录重映射与正文保真**：
   - 导入时允许用户为目标软件指定当前机器的工作区路径（映射本地元数据）；
   - **正文绝对保真**：对话原文中的所有代码、路径、历史文件提及均原样保留，**严禁做出“不会将旧系统路径混入上下文”的虚假承诺**。

### 4.3 未完成轮次交互规范
- 对于用户发问后被中断、AI 尚未作答的未完成轮次：
  - 界面呈现用户原始提示词，并打上 `[轮次未完成 · 等待模型答复中被中断]` 占位标记；
  - **不承诺自动续写**：文案明确说明“系统仅保留提示词原文。目标软件**不会自动代跑旧指令或继续生成**，导入后需由你在目标客户端中主动发送新消息”。

### 4.4 续聊确认交互语义修正
- 用户拉起终端或目标软件进行测试后返回界面：
  - 界面操作按钮命名为：`「记录：我已手动续聊」`（取代原先的“标记续聊已验证”）；
  - 状态标签更名为：`[用户确认已续聊]`；
  - 辅助说明：“此状态仅代表用户主观确认已发送下一条消息，不代表通过端到端自动化测试、多系统双向测试或软件重启读回验证。”

## 5. 状态矩阵规范（定向修订后）

| 状态 | 界面表现 | 约束与操作 |
|---|---|---|
| **1. 正常会话 (已读回)** | 纯净问答流，无工具冗余 | 仅包含用户原文与最终答复；代码块支持复制；允许导出预览。 |
| **2. 待续聊验证** | 顶部横幅：`[已写入目标存储 · 待续聊验证]` | 按钮为`「记录：我已手动续聊」`；不复制未经真实验证的目标伪命令。 |
| **3. 最终答复不可判定** | 答复卡片打上警告框，顶部显示红色阻断横幅 | **强行阻止导出与写入恢复**；不提供勾选携带旁路；卡片不标“Final Answer”，不显示未过滤日志。 |
| **4. 未完成轮次** | 虚线边框占位卡片 | 仅展示用户原文；明确提示“目标软件不会自动代跑旧指令，后续需主动发问”。 |
| **5. 当前版本能力未验证** | 顶部横幅：`[当前版本的恢复能力尚未验证]` | 严谨客观表述（不妄断不可能）；**禁止推荐跨软件转换**；锁定不可用的写入操作。用户确认/目录映射绝不可提升其能力。 |
| **6. 重复导入冲突** | 弹出冲突处理模态框 | **默认跳过/打开已有**；明确选择时另存副本；**严禁提供覆盖更新**。 |
| **7. 目标目录映射** | 顶部路径条显示本机工作区 | 仅映射目标逻辑元数据；用户及答复正文中的旧路径 100% 保真，不作消除承诺。 |
| **8. 历史查询为空** | 依据 Codex 探针特别增加的状态标记 | 提示“历史查询为空，桌面UI展示未验证；最新本机模拟请求已进入下轮但非真实模型续聊”。 |
