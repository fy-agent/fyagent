# 第七轮滚动与弹窗来源完整性及根目录治理

## Goal

让长内容在所有产品页面实际可滚动到达，补齐用户触发弹窗的来源连续性，并按工具发现与维护合同收敛仓库根目录，防止共享组件已存在但业务入口漏用。

## Background

基线为 `4f8973ef`，`dev/laiyongjie` 开始时工作树干净、无活动任务。保留第六轮的单一前端、双蓝色主题、Radix/Motion/原生动画所有者、原生权限与敏感内容清理，不改主导航和业务流程。
用户报告 Skills 等页面无法滚动，部分按钮触发模态框没有来源展开，并补充账号移除确认框是明确案例。根目录现有脚本配置须逐项核实用途，不能按扩展名批量删除。

## Acceptance Criteria

- [x] 滚动问题先有基线复现，长数据场景使用真实滚轮及键盘，不以脚本 scrollTop/自动 scrollIntoView 冒充用户可达性。
- [x] 七主路由和各页签形成滚动所有权清单；窄/宽容器、空/长数据、页签切换、模态关闭后均不困住内容，草稿与原有导航保持。
- [x] 全部共享 Dialog、包装组件、调用点及触发入口完成来源清单；瞬态菜单、异步结果、嵌套确认与持久触发分别验证。
- [x] 账号移除影响预览在立即、开场中途、开场之后返回，以及失败/取消/重开时，都有正确来源和连续呈现；不延迟预览请求、不提前删除、不延后取消。
- [x] 减少动态效果、来源不可用、程序化入口中性过渡；不复制表单、令牌、正文或整页截图作为动画。
- [x] 根目录逐项记录保留/迁移/删除依据；移动同步脚本、测试、CI、格式/类型检查、有效 SPEC 和上下文引用；不留下第二套兼容入口。
- [x] Chromium 四桌面尺寸及 WebKit 关键路径、统一单元/类型/lint/构建/完整门禁通过；生产性能与最终组合验证不放宽阈值。
- [x] 全部本轮任务归档、工作提交可追溯、Journal 记录、最终工作树干净；未测原生环境如实标记。
