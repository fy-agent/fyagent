# 修复 #141 的 Prompt 与 Daily Memory 两项 P1

## 目标与依据

消除 0.4.4 已实际复现的数据清空与记忆列表失败，保持现有正常操作可用。基线为 main / v0.4.4：2f264d2f89326601a33f610c72a9f0143306d066。前一轮隔离安装版复验记录在 本机 0.4.4 复验包中的 issue-141-current-findings.md。

用户已授权在独立分支先规划、确定回退后连续完成修复、验证。本次不等待重复的流程确认。范围只包含这两项，不关闭整个 #141 汇总票。

## 要求与验收

- P1-A：新建、编辑或从文件导入未启用 Prompt，只更新对应应用的提示词库；已有 live 文件逐字节保持，缺失 live 文件仍缺失；不生成或轮转 live 恢复副本。
- P1-A 导入身份：每次显式导入创建独立库记录，连续或同一时间值的导入不能替换已启用条目；已有记录ID保持兼容。
- P1-A 兼容：显式启用、编辑已启用条目及真正 enabled→disabled 的操作保留现有生效/停用语义；禁止删除已启用条目的规则保持。应用之间数据隔离。
- P1-B：Daily Memory 的列表与搜索只返回严格有效的 YYYY-MM-DD.md 文件；README.md、非法日期、备份文件和同名目录不会让合法条目整页失败。
- P1-B 兼容：合法日期（含闰日）正常读取、保存、搜索与倒序排列；直接读/写/删非法名称与日期在文件操作前失败。复用已有日期语义，不另建解析器或放宽前端校验。
- 新增回归用例必须先在旧实现失败，再在修复后通过。保留重要旧行为测试。
- 使用分支源码构建的本机应用和全新隔离资料，重跑两个原生 GUI 场景并回读文件/数据库。原安装版不替换，真实账号和资料不写入。
- 完成相关检查、变更审阅、文档更新与独立提交；保存精确源码/构建/测试证据和回退说明。

## 非目标

#141 的其他 UI/Windows finding，账号复用、UCP #55/#57/#59、窗口设计、历史丢失内容的自动恢复、新增 IPC/数据库迁移/依赖/全局配置、正式 Release 或部署。

## 关闭边界

两项缺陷修复可以在本分支验收；未合并/未发布前不称为主线或生产修复，也不将 #141 整票关闭。
