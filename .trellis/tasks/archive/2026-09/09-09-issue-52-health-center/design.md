# 产品方案与实现设计

## 方案比较与选择

| 方案                                    | 好处                                                     | 代价                                           | 决定       |
| --------------------------------------- | -------------------------------------------------------- | ---------------------------------------------- | ---------- |
| A：全部放在 Agent 卡片内                | 就近、入口少                                             | 12 项检查淹没安装与配置主操作，跨 Agent 排障难 | 不选       |
| B：独立健康仪表盘                       | 状态集中、可扩展                                         | 与原目录脱节，可能复制登录/安装流程            | 不单独采用 |
| C：共享状态快照 + 独立总览 + 原卡片直达 | 集中排障同时保留操作上下文，现有流程继续作为唯一操作入口 | 需要一个小的只读汇总层和导航接线               | 采用       |

独立页面名为“运行状态”，沿用当前蓝灰桌面产品的字体、尺寸、边框、明暗主题和控件。页面先呈现需要处理的软件与具体原因，详情按安装与启动、账号与配置、连接与使用组织。无需健康分数、仪表盘图表、庆祝动效或大幅营销文案。

## 视觉约束

使用现有 `--fy-surface-*`、`--fy-text`、`--fy-text-secondary`、`--fy-accent-*`、`--fy-border`、`--fy-radius-*` 与字体角色 token；页面标题 22px、区段16px、正文14px、辅助12px。状态用文字/图标加语义颜色。复用 Button、FeatureSearch、CatalogMasterDetail/现有布局能力、PersistentSurface，避免新控件体系。信息优先，健康状态不能挤掉目录主操作。

## 数据与安全

新增 `get_agent_health(agentId)` 只读 native 命令，由 service 汇总现有安装 inventory、受管连接元数据、配置、proxy 和当前 Agent 的本机请求记录。命令只接受封闭 Agent ID；不接受路径/URL/命令。不返回密钥、文件原文、绝对路径、账号标识、请求内容或任意错误文本。

复用可证明无副作用的底层 owner，禁止调用 `readiness_for` 的远端版本路径、目标 CLI、OAuth refresh、模型列表/付费探测、Provider 写入、usage 导入。逐来源失败变为明确 unknown/read_failed，不污染其他来源。每次返回完整的 12 项，采样时间与最近使用的事件时间分开。

共享 TypeScript 合同 `health.ts`，原生端口从 unknown 严格解析；Query 负责快照，页面只做选择/展示。快照 5 分钟过期；刷新失败保留旧值并标过期。批量刷新串行且可停止继续派发，隐藏页面停止自动检查，重新可见时回读以验证修复结果。正常状态只由有证据的检查计算，unknown 关键项不会成为 ready。

## 处理入口

仅使用封闭动作 installation/configuration/authentication/model_test/refresh，由前端映射现有内部路径。模型测试进入已存在的模型表单，继续明确确认；不在总览自动发送请求。状态页 URL 只携带已验证 Agent ID，修复流程返回使用浏览器历史及保留的状态页选择，不引入任意 returnUrl。

## 复用判断

没有新增依赖。React Query、既有 Radix 控件、Tauri、serde、Tokio、现有配置解析器与 DAO 足够；新增的业务状态聚合属于 FyAgent 专有规则，不需外部健康检查框架。来源表见 research/current-health-sources.md。
