用户已授权拉取分支、比较方案、自主选择、创建目标并完整实现。基于 `11c13339`（与 `81e06aae` 文件树一致） 的隔离分支 `codex/issue-52-health-center`；原 `~/fyagent` 的未提交工作保留。

## 用户问题

用户已有多款 AI 软件，安装、登录、模型和配置的信息分散。出错时不知道问题属于哪一步，也不知道处理后是否改善。用户需要的是“哪个需要处理、为什么、下一步在哪里”，不是更多配置表单。

## 选定结果

增加“运行状态”主页面；各 Agent 卡片可直接进入对应详情。页面共享一套真实本机健康快照，修复导航回原有安装、账号、模型或恢复流程。覆盖目录全部 Agent，能力未知和不支持如实呈现；Codex、Claude 为主要完整交互验收路径。

## 验收

- [x] 按 Agent 显示 Ready / Needs attention / Blocked / Not configured / Stale 的明确中文状态、原因、最后检查时间。
- [x] 每个 Agent 的详情覆盖版本与来源、Helper、安装冲突、配置、凭据状态、服务地址、登录、模型、配置漂移、本机转发、重启需求、最后真实请求共 12 项；缺少事实显示待确认或不支持，不能靠占位正常值通过。
- [x] 每项有严重度、稳定原因、检查时间和合适的处理入口；正常/无需处理项不强行提供修复。
- [x] 本机检查单个或批量重跑，保持其他 Agent 的结果；部分失败不清空成功结果，过期/失败/隐藏页面不伪造新结果。
- [x] 默认检查不联网、不启动目标 CLI、不刷新授权、不写用户配置或同步 usage；付费测试/登录/配置改变只进入已有明确用户操作流程。
- [x] 从 Agent 卡片进入对应状态；进入处理页再返回可得到新状态，保留选择；隐藏页面不后台轮询或继续派发检查。
- [x] 键盘、空状态、错误、窄窗口、明暗主题和必要可访问性通过浏览器交互检查，生产构建通过启动检查，性能对照如实记录；本机 IPC 与只读边界有独立测试/回读。
- [x] 相关源码规范、类型/格式/lint、单元、Rust 和生产浏览器检查通过；串行执行性能采样并给出相同宿主的主线对照，明确未达预算项；提交推送工作分支并交付可审阅 PR，不合并、不发布、不自行关闭 Issue。

## 产品边界

Ready 表示本次支持的本机检查通过；实际模型请求证据单独显示，不暗示额度或远端服务可用。未知关键配置不会产生 Ready。最后请求只展示本机已记录且归属当前 Agent 的结果，不用其他 Agent 或全局流量冒充。状态不会触发静默修复。

不扩展新的安装器、认证提供商、云账号、定时守护、跨设备同步或自动恢复系统。复用现有页面和确认机制。
