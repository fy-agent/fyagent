# 实施与验收计划

本轮状态：planning。仅交付规划，未授权在本轮开始实施。

## 1. 锁定基线

- 回读 research/module-scope.md，确认模块实际存在的分支、commit、远端与目标交付分支。
- 核对该版本的 AGENTS、前后端规范、构建脚本及脏改动。当前旧交互分支不是删除工作已完成的证据。
- 在正确基线上使用独立工作树，保护现有用户改动；迁入本规划的副本或准确引用。
- 对实际模块标识生成引用清单，区分专属实现、共享依赖、当前说明与历史记录。

## 2. 移除产品功能

- 移除入口、页面及子流程、路由注册、页面保活注册、项目选择/绑定和跨页跳转。
- 移除专属 hooks、状态、类型、查询键、接口、mock 和资源。
- 移除原生命令注册、专属服务、数据模型和不再使用的依赖。
- 清理启动初始化、备份恢复、导入导出、快捷入口和开发预览中的关联项；以实际引用为准。
- 停止旧数据读写；保留用户历史文件和共享配置。核对旧路由恢复与旧备份兼容行为。

## 3. 同步现行资料

- 更新手册、功能概述、相关规范及确实受影响的截图；清理专属文案和示例。
- 删除只验证已删除功能的测试，保留/补充能证明入口退役、旧状态安全回退、共享配置不受损的测试。
- 用变更说明标记旧功能已退役，不清空历史任务与发布证据。

## 4. 验证

- 执行实际基线定义的类型检查、前端构建、lint 及受影响测试；若是当前 V2 结构，使用 pnpm typecheck:v2、pnpm lint:v2、pnpm test:v2、pnpm build:renderer，并补相应路由浏览器验证。
- Rust 发生改变时遵循实际基线规范执行格式、clippy 与相关测试（当前合同入口为 mise run rust:fmt:check / rust:clippy / rust:test）。
- 打开真实运行版本核对：导航无模块、旧入口回到有效页面、核心配置流程仍可用、无调用缺失命令的错误。
- 使用临时数据目录覆盖空安装与含旧项目数据的升级场景；验证数据未被误删、模块不会被重新加载。不得在用户真实数据上做破坏性试验。
- 搜索模块真实标识并逐项解释残留，允许历史记录与必要回归用例，不允许活跃业务代码残留。
- 验收证据须来自最后一次修改之后；Mac 验证不代表 Windows 实机通过。若跨平台运行行为受影响，列出对应验证或明确未验证项。

## 5. 交付

- 对照 PRD 验收条件逐项回读，提供变更清单、检查结果及历史数据位置说明。
- 本规划不包含自动发布、合并 PR 或清空历史数据。

## 执行分工

前端与后端删除在实际依赖清单明确后可分给两个执行者，各自拥有不同文件；集成人负责共享类型、文档边界、旧数据行为与最终检查。若模块实际规模很小，合并为一个实现工作包，不人为拆碎。
