## 用户结果

1. 支持的软件能够查询其正确发行渠道的版本；产品版本、日期标签、CLI 和 Desktop 不互相混用。
2. 下载源能够准确报告可达性、版本同步程度、完整性及支持的架构。
3. 已开放的一键安装在支持平台上完成下载、安装/升级、版本回读和启动。
4. 通过现有门禁提交 PR 并交付可验证的新补丁 Release。

## 验收标准

- 每个入口记录检验时间、commit、平台/架构、官方版本、选中来源、来源版本与结果。
- 状态区分：官方确认、镜像回退且最新性未知、镜像滞后、缺包、完整性不匹配、网络失败、架构不支持。
- 废弃、替代或新分发渠道必须有官方证据，不能仅据 package 名相似作修改。
- 保留精确版本、产品身份、HTTPS、重定向边界、完整性、签名和普通用户执行隔离。
- 版本显示正确不能代替成功安装；安装向导启动不能代替安装后回读。
- 同一版本的完整 artifact、发布 manifest、checksums、signing-status 和构建证明一致。
- 所需 CI、平台原生验收和正式 Release 工作流完成，用户可实际下载新版本，才可关闭任务。
- 任何未完成项目、被跳过测试或环境阻塞不得标记为通过。

## 排除范围

不重构无关页面，不扩展支持系统，不迁移用户账号/配置，不禁用签名，不直接改旧 Release 标签。
不以宿主机源码检查替代用户授权虚拟机中的执行；后续 agent 必须读取当前环境授权限制。
