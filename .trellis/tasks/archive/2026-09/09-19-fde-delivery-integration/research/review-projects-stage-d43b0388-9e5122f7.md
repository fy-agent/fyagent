## 1. P2：同时编辑名称与工作说明后，两个保存入口互相锁死

位置：`src/pages/projects/Page.tsx:460-466`、`:491-495`。

步骤：打开已有项目，修改项目名称，再修改工作说明。保存名称以 `text !== context.content` 为禁用条件；保存工作说明又以 `name !== project.name` 为禁用条件，因此两者都不能点击。用户必须手工还原一个字段或放弃草稿，不能完成普通的“修改项目资料”操作。当前 3 项 UI 测试只覆盖单独说明编辑，没有覆盖这个路径。

最小修复：让两个字段能作为一份草稿保存，并正确延续 native 返回的新 revision；或保留独立保存，但保存其中一项后保留另一项草稿。不能只移除 disabled 条件：当前 editor 的 key 包含 projectRevision，首次保存后的重挂载会丢弃另一个草稿。补一项同时编辑两字段并最终读回两者的交互测试，失败时也应保留草稿。

## 2. P2：工作说明文件异常会封锁整个项目，而且没有新版本恢复入口

位置：`src/pages/projects/Page.tsx:258-277`；关联 `src-tauri/src/services/projects/mod.rs:273-275`、`:289-293`。

步骤：保存工作说明后，在外部移动/删除 `context.md`，或修改生成的 `workspace/AGENTS.md` / Codex 配置使回读检测失败；重新进入/刷新项目。安全回读正确拒绝已变化文件，但页面直接用错误 EmptyState 替换整个 ProjectEditor，导致改名、移除引用、归档、交付包和验证面板一起消失，只剩重试。native 的 write_context、prepare_codex 又必须成功读取旧 generation，不能创建一个新版本来修复。旧文件内容已经丢失时，用户只能放弃整个项目另建一个，甚至不能在 UI 归档原项目。
