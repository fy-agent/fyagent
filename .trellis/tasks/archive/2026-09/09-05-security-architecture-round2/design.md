# 设计与兼容性边界

## 决策

1. 依赖治理以具体 advisory 和实际解析图为依据。npm 只更新受影响包及必要父节点：Vitest 2 -> 修复的 3.2 分支，Vite 保留 7，Tauri 保留 2；Rust patch/minor 更新优先。保持锁文件可复现，不能用 broad overrides/禁用审计代替修复。
2. HTML 结构由 parse5 负责，预览特有的资产限制/内联/信任策略仍在 FyAgent 薄适配器。使用位置范围替换以保留构建输出原文，禁用自造标签解析及单次字符串“消毒”。普通文本呈现使用 DOM textContent/文本节点，不再将用户值拼接入 innerHTML。
3. Provider 身份判断使用标准 URL 解析及精确 hostname/受控子域判定；抽取到现有 renderer-neutral/所属 provider helper，四个调用点共用。不是通用 URL allowlist，也不授权把凭证发给任意匹配标签的站点。
4. 日志只记录必要的事件、状态、数量和封闭错误类别。不通过对秘密做哈希建立长期关联标识；真实 refresh/token 逻辑不改。原生 RNG/指针告警先核对生命周期和 bounds，不为了让静态分析安静而降低内存安全。
5. dependency-cruiser 使用项目 TypeScript 解析器。架构规则守护真实边界，类型依赖和运行依赖分别解释。若发现环，拆出中立契约/配置，由组合根注入实现，不批量搬文件。保留现有精确 ACL/架构测试，图扫描补充它们而非替代行为回归。
6. 第三方、测试值及历史告警记录精确证据，不批量 dismiss。密钥扫描始终 redact，不将原始 secret 或其值衍生散列写入研究/日志。

## 失败与回滚

- 每个独立工作流保持局部提交/差异可审查；测试或 API 不兼容时退回设计，不放宽检查。
- 运行时协议、数据库版本、权限集合和签名流程不变。纯 JS parser 只属于开发/构建工具，不加入客户端运行包。
- 平台源码摘要按实际 diff 逐一复核后更新，不新增 scanner exclusion。最低 WebView 能力不得通过现代便利 API 被意外提高。
- 远端告警来自 main；本地修复未合入远端前，不能宣称 GitHub 告警已经关闭。
