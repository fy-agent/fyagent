## 2. 一句话定义

FyAgent 用两个互补页面管理本机 Agent 的长期上下文：

- **提示词：管理“Agent 应该怎样工作”。** 把可复用规则组合后，注入每个 Agent 实际读取的指导文件。
- **记忆：管理“Agent 已经留下了什么”。** 读取长期记忆、每日记录和会话来源，再把用户确认的结论同步到需要它的 Agent。

页面不以 Codex、OpenClaw 或某一种文件格式为中心，也不假设每个 Agent 都有同一种记忆能力。

## 3. 产品依据：本机真实结构

本轮只读扫描到 6 个工具、8 个 Agent 实例：Codex、Claude Code、Gemini CLI、OpenCode、OpenClaw 的 `main / utility / group_liaison`、Hermes。

| 事实 | 产品影响 |
| --- | --- |
| Codex、Claude Code 已有全局指导文件；Gemini CLI、OpenCode 的候选全局文件尚未创建 | 提示词目标要显示“已存在 / 启用时创建” |
| OpenClaw 的 `main` 与 `utility` 共用一个 workspace，`group_liaison` 使用另一个 workspace | 目标不能只用应用名；必须有实例、workspace、路径，并按路径去重写入 |
| 长期内容既有 Markdown，也有 Codex 派生记忆、OpenCode/Hermes SQLite 索引 | 记忆不能退化为 Markdown 文件浏览器 |
| 会话存储分布在 JSON、JSONL、SQLite、trajectory、transcript 等结构中 | 后端需要逐工具 adapter，前端统一展示来源和能力 |
| `AGENTS.md / CLAUDE.md / SOUL.md` 与 `USER.md / MEMORY.md` 语义不同 | 提示词与记忆不能同时编辑同一类文件 |

完整证据见 `research/local-agent-inventory.md`。原型数据只保留匿名化结构，不复制本机私人正文。

## 4. 用户任务

### 4.1 第一次配置 Agent

用户的指导文件可能为空或不存在。用户要从 FyAgent 提炼的规则库中选择需要的规则，并一次分配给一个或多个真实目标文件。

### 4.2 在多个 Agent 间保持一致

用户不希望在 Codex、Claude Code、OpenCode、OpenClaw、Hermes 等工具里重复维护语言偏好、协作方式、完成标准和代码质量规则。

### 4.3 找回和复用已有上下文

用户要知道每个 Agent 已经有哪些长期记忆、每日记录和会话历史；从原始记录中挑出可复用结论，确认后再同步，而不是自动复制全部聊天。

### 4.4 分清作用域和归属

用户要看懂一条内容属于哪个工具、实例、workspace 和文件；共享路径只处理一次，未创建或只读来源必须明确展示。

## 5. 提示词模块

### 5.1 产品对象

导航沿用“提示词”，但页面中的实际对象是**可组合的长期规则模块**，不是一次性聊天 Prompt。每条规则至少包含：

- 稳定 ID、名称、用途描述和 Markdown 正文；
- 类型：通用规则、角色与表达、执行流程、验收规则、记忆规则、自动运行或自定义；
- 来源：本机规则提炼、官方基础模板或用户创建；
- 独立启用状态；
- 零个或多个注入目标；
- 更新时间和后续真实同步状态。

### 5.2 首批内置规则

首批内容来自本机现有全局规则的匿名化结构，并用各工具官方指导文档校准：

1. 中文与回复风格。
2. 目标、边界与完成证据。
3. 先读项目上下文。
4. 规划与方案对比。
5. 最小改动与真实验证。
6. 代码审查。
7. 记忆读取与写回。
8. 工具失败先定位根因。
9. 定时任务与心跳边界。

仓库命令、真实目录、密钥位置和单次任务步骤不进入通用内置规则；它们应来自项目级指导文件或按需 Skill。

### 5.3 页面结构

#### 顶部

- 标题“提示词”和一句用途说明。
- 不显示 Codex 胶囊。
- 主操作“新建提示词”。

#### 左栏：提示词库

- 搜索名称、描述、正文、类型和来源。
- 显示名称、规则类型、用途、目标数量和独立开关。
- 选中表示“当前查看/编辑”；开关表示“是否参与组合”，两者互不替代。
- 多条规则可以同时启用。

#### 中栏：规则详情

- 编辑名称、描述和 Markdown 正文。
- 保存仅更新当前规则；原型明确反馈“已保存到前端预览”。
- 新建规则默认未启用、无目标，不会自动写入所有 Agent。

#### 右栏：注入目标

- 展示工具、作用域/实例、真实目标路径和文件存在状态。
- 当前扫描映射为 7 个目标文件、覆盖 8 个 Agent 实例。
- 同一工具可有多个 workspace 目标；共用同一路径的实例合并展示并只写一次。
- 显示规则来源、类型、更新时间和“托管区块保护”说明。

### 5.4 关键交互

- 启用一条规则不会关闭其他规则。
- 启用规则必须至少有一个目标；已启用规则不能直接移除最后一个目标。
- 目标多选属于当前规则草稿，保存后才写回页面列表状态。
- 搜索不修改启用或选中状态。
- 切换条目、新建或切换路由前，未保存草稿需要确认放弃。
- 原型阶段所有动作都可点击，但不调用 native API，不显示“已写入 Agent”。

### 5.5 真实注入规则

真实接线后按目标路径执行：

1. 取得该路径所有已启用规则，按稳定顺序 compose。
2. 生成预览，显示来源规则、目标路径和最终内容。
3. 比较上次同步摘要与当前文件，发现外部修改则进入冲突状态。
4. 只替换 FyAgent 受管区块，保留区块外用户内容。
5. 原子写入、回读校验并返回逐目标结果。

## 6. 记忆模块

### 6.1 产品对象

记忆页不强造一套抽象分类，而是贴近本机真实存储生命周期：

- **长期记忆**：用户画像、稳定偏好、决定、经验、派生摘要和工具级长期记录。
- **每日记录**：按日期或专题保存的短期工作痕迹。
- **会话记录**：JSON/JSONL/SQLite 中的任务、消息、transcript、trajectory 和可搜索索引。

“跨 Agent 共享”是长期记忆的同步能力，不是必须单独理解的第四种数据。

### 6.2 页面结构

#### 顶部

- 标题“记忆”和扫描范围说明。
- Tab：长期记忆、每日记录、会话记录。
- 主操作“重新扫描本机”；原型返回识别到的工具/实例数量。

#### 左栏：真实来源

- 按当前分类搜索标题、工具、用途、路径、存储格式和内容。
- 显示来源工具/实例、Markdown/JSON/JSONL/SQLite 等格式、文件或记录数量、同步状态。
- 数量和更新时间是扫描结果，真实接线后由后端动态返回。

#### 中栏：预览与编辑

- 长期 Markdown 记忆在 adapter 允许时可编辑。
- 派生数据库记忆、会话来源和其他只读对象明确显示“只读来源”。
- 每日/会话内容可“提炼为长期记忆”；只复制草稿和来源引用，不改原始记录。
- 本机私人正文不作为 prototype seed；页面只展示结构性示例。

#### 右栏：来源与同步

- 展示工具、实例/作用域、存储格式、位置、可读写/可搜索能力、数量、状态和更新时间。
- 长期记忆可多选已验证的目标，并生成逐目标同步任务；当前原型只列 Claude Code 本机规则引用的记忆目录、两个 OpenClaw 原生 workspace 和 Hermes 原生 memories，共 4 个目标。
- Codex 派生记忆、Gemini 会话与未被 OpenCode 指导文件引用的维护文件当前只作为来源，不把“磁盘上有文件”误报成“Agent 会读取”。
- `AGENTS.md / SOUL.md / TOOLS.md / HEARTBEAT.md` 等上下文索引只读展示，明确转到提示词页管理。
- 每日/会话来源提供“提炼为长期记忆”，不直接向所有 Agent 广播。

### 6.3 当前真实来源范围

- Codex：会话索引、rollout、派生记忆与 SQLite 状态。
- Claude Code：长期记忆、用户画像、项目 JSONL、history 和 transcripts。
- Gemini CLI：项目会话 JSONL；当前未发现原生长期记忆文件。
- OpenCode：`MEMORY.md`、日期文件和 session/message SQLite。
- OpenClaw：两个 workspace 的长期/用户/每日文件，以及三个实例的 session/trajectory。
- Hermes：`MEMORY.md`、`USER.md`、JSON session 和带 FTS/trigram 的 SQLite。

### 6.4 关键交互

- 分类和来源切换保留各自搜索与选中项。
- 可写长期记忆修改后，原“已同步”状态变成“待同步”。
- 有未保存修改时不能直接切换分类、来源、扫描或提炼。
- 同步前必须先保存并至少选择一个目标。
- “提炼”创建新的长期记忆草稿，保留来源，原始每日/会话记录不变。
- 同步按钮在原型中只生成本地任务反馈，不宣称文件已写入。

### 6.5 语义边界

| 内容 | 主责页面 | 说明 |
| --- | --- | --- |
| `AGENTS.md / CLAUDE.md / GEMINI.md` | 提示词 | 长期工作规则 |
| `SOUL.md / IDENTITY.md` | 提示词 | 身份、表达和边界；不是用户事实 |
| `USER.md / user_profile.md` | 记忆 | 稳定用户资料和偏好 |
| `MEMORY.md / 派生摘要` | 记忆 | 长期事实、决定和经验 |
| daily / session / transcript / trajectory | 记忆 | 原始或短期痕迹，提炼后才进入长期层 |
| `TOOLS.md / HEARTBEAT.md` | 提示词高级规则 | 工具与自动运行上下文，不默认跨 Agent 同步 |

## 7. 数据与同步原则

1. **扫描与内容分离**：先返回来源、能力和数量，再按需读取正文，避免一次扫描加载所有私人会话。
2. **来源可追溯**：提炼或同步后保留源工具、实例、workspace、资源路径、时间和摘要。
3. **目标按能力筛选**：没有长期记忆写入能力的 Agent 不显示为可同步目标。
4. **逐目标状态**：至少区分待处理、同步中、已同步、冲突、失败、不支持。
5. **部分成功真实表达**：一个目标失败不抹掉其他结果，也不能显示为整体成功。
6. **不静默覆盖**：外部修改、lock、版本变化或路径共享都必须在写前处理。
7. **原始记录只读优先**：会话和每日记录用于检索与提炼，不作为跨工具整库复制对象。

## 8. 现有后端评估摘要

### 可复用

- Prompt 的名称、描述、正文、单应用启用状态和时间字段。
- 旧 Prompt 文件映射、读取和基本写入能力。
- OpenClaw workspace 白名单文件与 daily 记录的读取/写入/搜索。
- Hermes `MEMORY.md / USER.md` 读取、限制和启用状态。

### 不能支撑新页面

- 没有本机工具/实例/workspace/资源的统一扫描合同。
- Prompt 仍是按应用复制、同应用单选，并整文件覆盖。
- 没有多目标、稳定组合顺序、受管区块、路径去重、冲突和逐目标结果。
- Memory 没有 Codex/Claude/Gemini/OpenCode/OpenClaw session/Hermes SQLite 的统一 adapter。
- 没有长期记忆目标映射、来源引用、提炼关系和逐目标同步状态。

完整字段清单和工作分解见 `research/product-model-backend-gap.md`。
