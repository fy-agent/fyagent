# 第八轮分配区响应式与内容利用率

## Goal

修复 Skills/MCP 应用分配在窗口调整后的错排，让详情卡片中的文字和操作合理利用自身容器宽度，并由共享规则管理相同职责的布局。

## Background

基线为 `5d426392`，开始时 `dev/laiyongjie` 工作树干净、无活动任务、无额外 worktree。用户提供的截图显示 Skills 应用分配区在缩放后出现不均匀空隙、批量操作换行错乱，详情内容偏窄而右侧留白过多。生产构建加合成数据在 Chromium/WebKit 完成连续缩放复现；不读取用户真实安装数据。

## Requirements

- R1：Skills 与 MCP 应用分配、批量分配在窗口连续缩放及分栏拖拽后仍对齐、可读、可滚动和可操作，七个既有目标不丢失。
- R2：详情成为三栏的主要可伸缩内容区，辅助分配栏有合理宽度；信息卡片、元数据及操作组按自身容器利用空间，同类采用集中维护的规则。表单、短字段和长文阅读保留不同职责，不强制一个全局百分比。
- R3：保持七个主导航、分栏流程、双主题、草稿、真实滚动、来源动效及原生读写权限不变；优先复用现有库和原生 CSS 能力。
- R4：先记录源码、复现与官方来源，再补齐设计和执行计划；实现后同步 SPEC、验证、提交归档并交付干净工作树。

## Acceptance

- [ ] 两类现象具有本轮基线证据和共享调用方清单，不把主观留白判断当作测量结论。
- [ ] 连续大→小→大窗口变化、分隔条拖拽、断点两侧、长文本和双主题下，分配区无遮挡/丢控件/错排；键盘和滚轮实际可达。
- [ ] 详情名称、数值和长路径按自身容器分配空间，同类布局使用共享令牌；不放大字号、削掉数据或强行撑高卡片以填空。
- [ ] 七个既有目标、原有分栏节点、编辑草稿、焦点、隐藏页面、按压和弹窗来源行为保持；宽窄切换不会触发后台写操作，生产性能预算不放宽。
- [ ] 完整类型/lint/单元/浏览器/构建及预归档门禁通过；SPEC 更新、任务归档、Journal 和最终 Git 状态完整核验。

## Out of Scope

不新增产品功能、不换 UI/分栏框架、不改变整体导航及主题、不改后端合同或真实账号数据、不重写历史。安装路径的现行按需复制/隐藏策略不因“填空”而改为常驻显示。最低版本原生 WebView/GPU 未测不得声称通过。
