# 第二轮安全与架构治理

## 目标与价值

在第一轮共享机制重构之后，以真实安全告警和独立扫描识别仍然存在的风险，修复可验证的问题，建立可持续的依赖与架构边界。交付包含实现、测试、SPEC、审查记录、归档及干净工作树，不以扫描数字或机械拆文件冒充全仓无技术债证明。

## 已确认基线

- 本地 `dev/laiyongjie`，`b580bf90`，开始时工作树干净。
- GitHub 默认分支 `main`：51 项 open Dependabot、66 项 open CodeQL、2 项 open Secret scanning。CodeQL 快照源于 `5dcfb8ef`，不能直接当成本地现状。
- 独立 pnpm audit：35 个受影响依赖实例；cargo-audit：14 项 vulnerability，另有 informational/unsound/yanked 报告。
- Gitleaks：当前 HEAD 快照 17 项候选；本地 all refs 历史 2,769 commits / 32 项候选。扫描报告全量脱敏；候选不是已证实的私人凭证泄露。
- 初次临时 dependency-cruiser 环境缺 TypeScript，只扫描了 66 个 JS 模块，此结果无效，不得用于宣称 TS 架构无环。

## 要求

R1. 对三类 GitHub 告警逐组记录当前源码、调用路径、处置和验证；历史/测试/第三方告警不直接删除或关闭。
R2. 更新受影响依赖至经过核查的修复版本，保留主架构、包管理器、OS 产品范围和既有权限。需要跨不兼容版本时执行专项回归；无法安全消除的上游问题记录到具体依赖路径而非静默忽略。
R3. 收敛重复的 URL 身份判断及手写 HTML 解析，优先标准 URL 和已采用的成熟 HTML parser，修复实际注入/误判/扫描器实现问题。
R4. 检查日志、原生指针和随机数边界；移除不必要的敏感诊断，不用重写密码学、关闭测试或放宽权限处理误报。
R5. 对 renderer/scripts 执行真实依赖图扫描，修正明确违反层次/生命周期的依赖，增加自动化防回退约束；保持 V2、leftover、neutral 和平台边界。
R6. 建立可重复的安全复查依据，新增/修改代码覆盖成功、拒绝、畸形输入和兼容性用例。

## 验收

- AC1：三类远端告警和四类独立扫描均有版本、范围、日期、基线和脱敏结论。
- AC2：npm 审计无已知漏洞；Rust 可安全升级的已知漏洞完成修复，残余上游/条件问题明确列出，不通过 broad ignore 美化。
- AC3：URL 伪装、HTML 畸形标签、非结构化动态 DOM、平台扫描器空白等实际缺陷有回归。
- AC4：架构扫描确认 TypeScript 可用、覆盖真实源码，并纳入既有测试入口；不自建通用依赖解析器。
- AC5：修改不改变 IPC 名称/DTO/ACL、数据迁移、原生补偿顺序或用户秘密保管语义。
- AC6：前端、V2、Rust、构建、浏览器及 prearchive 门禁通过；原生平台未执行部分单独披露。
- AC7：相关 SPEC 在归档前同步；工作提交、归档、日志完成，最终工作树干净。

## 范围外

不重写 Git 历史、不撤销第三方 OAuth 客户端、不修改远端安全开关/告警状态、不推送或发布。不引入新 UI/状态/数据库框架，也不声称一次审查能保证未来永无漏洞或技术债。
