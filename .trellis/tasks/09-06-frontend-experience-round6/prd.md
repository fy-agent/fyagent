# 第六轮单一前端与蓝色主题交互整合

## Goal

收敛单一前端与自动化验证，修复选中态及提示词布局，加入双蓝色主题与连续状态动效，保护后端合并和启动边界

## Background

本轮基线为 `6117a7d9`，开始时 `dev/laiyongjie` 工作树干净，只有主工作区。
第五轮后已合并 Claude CLI / 可逆配置，并修复原生隐藏窗口的 Query 就绪问题。
这些后端与启动边界必须保留，不能以第五轮旧提交覆盖本轮基线。
用户提供的图片用于缺陷与色彩意图，不将图片中的真实账号资料写入夹具或记录。

- [x] 七个页面、登录各步骤、所有共享tabs/list镜片在亮/暗两主题和四桌面尺寸可操作；普通及辅助文字4.5:1、关键边界3:1按实际合成状态验证，增加文字实际绘制与遮挡证据。
- [x] 覆盖提示词空/有数据、嵌套详情、容器拖窄、缩放、重访和窗口变化；检查最小可用区域，不仅检查无横向overflow。

- [x] 导航延迟与逐帧动画成本分别报告；保留既有100ms回访p95与33.4ms暖态动画帧p95目标，不通过延时/关闭动画/增加超时掩盖问题。主题扩散全程分段采样，不只截首尾帧。
- [x] Chromium与WebKit的关键路径均运行；模拟IPC不冒充真实原生或凭据验证，未验证的最低系统/GPU行为明确标记。
- [ ] 保留最近后端合并/启动修复的合同；本轮全部任务归档后无活动任务、有效上下文引用、工作提交可追溯、journal已记录、工作树干净。

## Scope and Constraints

用户授权本轮任务创建与方案选型。规划按Trellis最终方案评审后进入实施。
不改七条主导航与业务流程，不重写Git历史，不无证据改变原生协议、账号授权、安装和可逆配置行为；不升级React/Motion等基础框架大版本。
相关后端问题先分类：直接由当前前端接入或合并影响的缺陷在所属合同内处理；无关重构不夹带。

## Task Order

1. `frontend-layout-integrity`：先恢复真实可用布局与文字，建立可靠基线。
2. `renderer-consolidation`：在行为回归保护下收敛源码、测试与工具链。
3. `frontend-blue-themes`：成套主题和原点扩散。
4. `frontend-state-motion`：步骤/按压/镜片运动及组合性能。
5. 本父任务负责跨任务评审、近期后端合同复核、最终完整验证及归档。
